# День 2 — IP-адресація, налаштування мережевої карти, діагностика та практика в Cisco Packet Tracer

> Конспект складено з аудіорозшифровки лекції. Технічна суть; повтори та організаційні репліки відкинуто.

## Частина 1. IPv4 — структура та маска

### 1.1 Базис

- У ЗСУ використовується **лише IPv4**. IPv6 можливий тільки від провайдера (Kyivstar, Vodafone, Starlink — при автоматичному отриманні).
- IPv4 = **32 біти** = 4 октети по 8 біт. Кожен октет — значення **0–255**.
- **Маска** вказує, яка кількість старших біт лишається сталою (мережева частина). Решта — хостова частина для призначення користувачам.

### 1.2 Допустимі значення октету маски

Октет маски набуває лише сталих значень (біти заповнюються зліва направо):

```
0, 128, 192, 224, 240, 248, 252, 254, 255
```

При введенні некоректної маски ОС видасть помилку валідації — це мінімальний вбудований чекінг.

### 1.3 Хости

| Тип | Приклади |
|---|---|
| Кінцеві пристрої | ноутбуки, планшети, камери, IP-телефони |
| Мережеві пристрої | комутатори, маршрутизатори, точки доступу |

## Частина 2. Мінімальний набір параметрів вузла

| Параметр | Коли потрібен |
|---|---|
| **IP-адреса + маска** | завжди — доступ у межах локальної мережі |
| **Основний шлюз (gateway)** | для виходу в інші мережі / інтернет; шлюзом завжди є мережевий пристрій (роутер) |
| **DNS** | для запитів за доменним іменем |

> DNS = «довідник»: підміняє доменне ім'я на IP. Сам нічого не маршрутизує. Рекомендований публічний DNS — `8.8.8.8` (Google): кеш-сервери розміщені у провайдерів → швидша відповідь. У корпоративних мережах може бути власний (непублічний) DNS.

**Приклад вузла:**

```
IP      : 192.168.10.2
Mask    : 255.255.255.0   (/24)
Gateway : 192.168.10.1
DNS     : 8.8.8.8
```

Без gateway PC взаємодіє лише в межах своєї підмережі. Без DNS — лише за IP.

## Частина 3. Розрахунок підмереж

### 3.1 Задача

Дано: `172.16.74.147 /26`. Знайти межі призначення адрес.

Алгоритм (ручний): перевести IP та маску у двійковий код → логічне **AND** → IP мережі; інверсія хостових біт → broadcast.

```
IP мережі (network) : 172.16.74.128
Broadcast           : 172.16.74.191
IP min (host)       : 172.16.74.129   (network + 1)
IP max (host)       : 172.16.74.190   (broadcast - 1)
```

Адреси мережі та broadcast — службові, на хости **не призначаються**. На gateway за конвенцією ставлять **першу** (IP min) або останню (IP max) адресу; на практиці частіше першу.

### 3.2 Інструмент

Замість ручного переведення — **IP-калькулятор** (вводиш IP + маску, отримуєш network/broadcast/min/max).

### 3.3 VLSM (Variable Length Subnet Mask) — *винесено на домашнє завдання*

Закономірність:

- ↑ розрядність маски → ↑ кількість підмереж, ↓ кількість хостів.
- ↓ розрядність маски → ↓ кількість підмереж, ↑ кількість хостів.

`/24` ділиться на дві `/25`, кожна `/25` — на дві `/26` … аж до `/31`. На практиці типові маски — `/24` та `/30`. `/31` сучасні роутери підтримують (point-to-point), але зазвичай не застосовується.

**Приклад розподілу** `192.168.100.0/24` (254 адреси) між відділами:

| Відділ | Хостів | Потрібна маска |
|---|---|---|
| A | 90 | /25 (126) |
| B | 45 | /26 (62) |
| C | 25 | /27 (30) |
| D | 6 | /29 (6) |

> Прикладна задача: видали `/22` з корпусу → поділити під батальйони/об'єкти на шматки `/27`, `/28` за реальною потребою адрес.

### 3.4 Чому не тримати всіх в одній `/24`

Сумарно відділи < 254 хостів → теоретично можна одну мережу. Але при одночасній роботі зростає **широкомовний домен** → деградація мережі. Також ризик: будь-який клієнт може «нахімічити» і потрапити в чужу мережу. Висновок → потрібна **сегментація** (через маски — найпростіший рівень; повноцінно — через VLAN).

## Частина 4. Налаштування мережевої карти (Windows)

### 4.1 Шлях

`Панель керування` → (режим «Великі іконки») → `Центр мережних підключень` → `Змінити параметри адаптера`.

Швидкий доступ: **Win+R** → `ncpa.cpl`.

Адаптери, які можуть бути: Ethernet, Wi-Fi, віртуальні (VirtualBox/VMware). Bluetooth-з'єднання для роздачі інтернету — застаріле, не чіпаємо.

### 4.2 Особливість Windows — класова адресація

При ручному введенні IP Windows автопідставляє маску за класом:

| Початок IP | Клас | Автомаска |
|---|---|---|
| 192.x | C | /24 |
| 172.x | B | /16 |
| 10.x | A | /8 |

> Критично перевіряти автопідставлену маску при розрядності > /24 — найпоширеніше джерело помилок. ЗСУ-мережі починаються з `10.x` → автоматично підтягнеться `/8`.

### 4.3 Індикація доступності в Windows

| Іконка | Стан |
|---|---|
| Будиночок | провід, є інтернет |
| Антени в квадраті | Wi-Fi, є інтернет |
| Глобус | немає доступу до інтернету (але IP може бути) |

Глобус не завжди проблема — можна штатно працювати в мережі без інтернету.

### 4.4 Метрика інтерфейсу (пріоритет маршруту)

За замовчуванням провідне з'єднання має вищий пріоритет. Змінюється: `IPv4` → `Advanced` → зняти автоматичну метрику:

```
Ethernet : metric = 1   (основний)
Wi-Fi    : metric = 2   (резервний)
```

Менша метрика → менша дистанція → основний інтерфейс.

## Частина 5. Діагностика з командного рядка

`Win+R` → `cmd`.

### 5.1 ping

```cmd
ping ukr.net
```

Показує: проходження DNS-запитів, доступність ресурсу, затримку (мс), **TTL**.

**TTL → кількість хопів.** Базові значення TTL за ОС-відповідачем: Windows = 128, Linux = 64. Якщо відповідь прийшла з TTL=120 → пройдено `128 - 120 = 8` маршрутизаторів. У межах однієї мережі (без переходу через роутер) TTL **не зменшується**.

### 5.2 Підбір MTU для VPN (WireGuard)

VPN з'їдає частину байтів під службову інформацію → крізь тунель може не пройти повний кадр. Підбір розміру пакета:

```cmd
ping --help          rem або: ping -?  (ключ L = довжина)
ping -l 1472 -f <ціль>   rem -f = Don't Fragment; зменшувати -l до проходження
```

Максимальний кадр Ethernet — 1500 байт; від нього віднімаються накладні витрати тунелю. Дослідним шляхом визначити `-l`, що проходить, і виставити відповідний MTU на MikroTik.

### 5.3 tracert

```cmd
tracert 1.1.1.1
```

Перевіряє проходження маршруту до цілі. Якщо ціль не пінгується — показує **на якому хопі** збій. Працює по TCP → повільніше за ping. Дозволяє визначити зону відповідальності: твоя мережа / вузол зв'язку / провайдер / глобальний збій.

### 5.4 ipconfig

```cmd
ipconfig            rem IP, маска, шлюз
ipconfig /all       rem повний: DHCP, час оренди (lease), MAC тощо
ipconfig /?         rem підказка
ipconfig /release   rem звільнити адресу
ipconfig /renew     rem запросити нову адресу
```

`/release` + `/renew` — найчастіше вживане для скидання й перезапиту IP від DHCP.

> На мережевому обладнанні (MikroTik) є вкладка **Tools** — діагностика без виходу в консоль Windows (яка інколи поводиться менш передбачувано за UNIX-подібні).

### 5.5 Алгоритм усунення несправності

1. Перевірити налаштування мережевої карти.
2. `ping` ресурсу. Пінгується → перезавантажити браузер. Не пінгується → шукати збійний вузол.
3. Локалізувати: точка доступу (відпав патч-корд), кабель (пошкоджений; осколок міг влучити в жилу — лінія візуально ціла, зв'язку немає), лінк до роутера, інтернет (несплата / сонячні бурі на Starlink / обрив оптики — червоний індикатор на медіаконвертері ONU).

> Корпоративний сегмент → обов'язковий **резервний канал**: оптика + 4G / Starlink / Tooway / SatCom / Inmarsat.

## Частина 6. Практика в Cisco Packet Tracer

### 6.1 Обхід ліміту облікового запису

Без авторизації Packet Tracer дозволяє зберегти лише 3 проєкти. Обхід: заблокувати утиліті доступ до інтернету в правилах фаєрвола Windows **або** просто вимкнути інтернет і запустити.

### 6.2 Тип кабелю

Packet Tracer підказує коректне з'єднання:

- Пристрої **різного** рівня (PC ↔ switch, switch ↔ router) → **прямий** кабель.
- Пристрої **однакового** рівня (PC ↔ PC, switch ↔ switch) → **кросовий** кабель.

Розпіновка прямого кабелю **T-568B**: біло-помаранчевий, помаранчевий, біло-зелений, синій, біло-синій, зелений, біло-коричневий, коричневий.

Стандарт горизонтальної підсистеми: лінк до 100 м (90 м магістраль + 5 м на робочому місці + 5 м на вузлі зв'язку). Більше — оптика.

### 6.3 Сценарій A — APIPA (точка-точка)

Два PC напряму, обом задати DHCP. За відсутності DHCP-сервера спрацьовує **APIPA** (Automatic Private IP Address) → адреса з `169.254.0.0/16`.

> Поява `169.254.x.x` на карті = **немає відгуку від DHCP-сервера**. Типова причина: PC завантажився раніше за роутер → перезапитати IP. Два вузли з APIPA-адресами з однієї `/16` усе одно взаємодіють між собою.

### 6.4 Сценарій B — статика в одній мережі

```
PC0: 192.168.10.2 /24
PC1: 192.168.10.3 /24
```

```cmd
ping 192.168.10.2
```

Затримка < 1 мс, TTL не зменшується (немає переходу через роутер). Застосування L2-взаємодії: спільна папка, мережевий принтер (USB-принтер розшарюється по мережі — комп'ютер стає сервером друку).

> Три PC без комутатора в одну площину з'єднати **не можна**: одна мережева карта = один лінк. Можна лише пари через ПК з двома картами (міст) — нетипова задача. Для трьох вузлів в одному домені потрібен **switch**.

### 6.5 Сценарій C — комутатор + ARP-симуляція

Switch Cisco 2960 — керований L2, протокол **STP** (захист від петель). Аргумент для керівництва: керований switch (дорожчий за делінк/тплінк за 2000 грн) економить час на пошуку несправностей.

**Режим симуляції, ARP + ICMP, запит PC2 → PC1:**

1. PC2 генерує **broadcast** ARP, щоб дізнатися MAC PC1.
2. Запит іде на switch. Адресна таблиця (порт ↔ MAC) ще порожня → switch розсилає на **всі** порти.
3. PC0 ігнорує (запит не до його IP), PC1 відповідає **unicast** ARP.
4. PC2 дізнається MAC PC1, MAC додається в ARP-таблицю → подальша взаємодія напряму.

Пристрій з **іншої** підмережі (`192.168.20.x`), підключений до того ж switch, відкидатиме чужі запити — запит навіть не вийде з PC, бо про ту мережу він нічого не знає.

### 6.6 Петля (broadcast storm) — демонстрація

Два switch з'єднати **двома** кабелями → петля. Трафік починає циркулювати по колу. На **некерованому** switch петля забиває пам'ять → за ~10–15 хв швидкість падає до нуля. На **керованому** (STP) — порт з найменшою MAC вимикається, петля гаситься.

> TTL у петлі **зменшується** (немає переходів — формулювання спірне; за стандартом L2-кадр TTL не має, шторм гаситься саме TTL на L3 та STP на L2). «Пакет смерті» — навмисно завеликий пакет для переповнення пам'яті інтерфейсу.
>
> Типовий кейс: прибиральниця/сторонній бачить невставлений патч-корд, з'єднує два порти → switch «вимахується», доводиться фізично відключати стійку по черзі.

### 6.7 Сценарій D — маршрутизація між мережами

Дві мережі через роутер Cisco 2901:

```
Мережа 1: 192.168.10.0/24  -> g0/0 роутера = 192.168.10.1
Мережа 2: 192.168.20.0/24  -> g0/1 роутера = 192.168.20.1
```

**Особливості Cisco проти MikroTik:** інтерфейси за замовчуванням **вимкнені**, треба піднімати:

```
Router> enable
Router# configure terminal
Router(config)# interface g0/0
Router(config-if)# ip address 192.168.10.1 255.255.255.0
Router(config-if)# no shutdown
Router(config-if)# exit
Router(config)# interface g0/1
Router(config-if)# ip address 192.168.20.1 255.255.255.0
Router(config-if)# no shutdown
```

При призначенні IP на інтерфейси роутер автоматично отримує **directly connected** записи на обидві мережі.

**Обов'язкова умова взаємодії** — на **кожному** PC прописати gateway:

```
PC у мережі 1: gateway 192.168.10.1
PC у мережі 2: gateway 192.168.20.1
```

Без gateway на відповідачі: запит дійде, але відповідь не повернеться. З'єднання роутерів — найшвидшими (гігабітними) інтерфейсами: Starlink дає 200 Мбіт; на 100-Мбіт MikroTik половина швидкості ріжеться на вході.

### 6.8 Сценарій E — домашній Wi-Fi роутер + NAT + DNS

Топологія: 2×PC — Wi-Fi-роутер — сервер (емуляція інтернету).

```
WAN (до "інтернету"): DHCP-клієнт від провайдера
LAN:                  DHCP-сервер роздає клієнтам
Сервер (емуляція):    203.0.0.0/24, увімкнути HTTP + DNS
```

Доступ до роутера: IP та логін/пароль на наклейці (типово `admin/admin`). Перевірка: браузер по IP → по домену (працює DNS).

**NAT (PAT):** роутер підміняє внутрішні «сірі» IP на зовнішню «білу». Зовнішній сервер бачить лише білу адресу, не внутрішню мережу. У зворотному напрямку — біла → сіра.

> Боль із практики: кілька TP-Link з однаковою `192.168.1.0/24` каскадом → при навантаженні IP-шторм через дублікати, мережа просідає. **Рекомендація:** змінювати третій октет LAN-мережі (не лишати дефолтні `192.168.0.0` / `192.168.1.0`). «+100 до карми».

**Потік DNS+NAT при заході на ukr.net:**

1. PC шле DNS-запит на `8.8.8.8` → отримує IP `ukr.net`.
2. PC формує запит уже за IP.
3. На виході роутер виконує NAT (сіра → біла), на вході — зворотно.

> Правило: **одна служба — один сервер** (для відмовостійкості). Тримати все на одному сервері можливо, але не рекомендовано.

## Підсумок ключових тез

- IPv4 = 32 біти / 4 октети; маска — сталі значення октету (0,128,…,255).
- Мінімум для виходу назовні: IP + маска + gateway (+ DNS для доменів).
- network та broadcast — службові; host range = [network+1 … broadcast−1].
- VLSM: ↑ маска → більше мереж, менше хостів.
- Windows підставляє маску за класом — перевіряти при > /24.
- ping → TTL → хопи; tracert → локалізація збою; ipconfig /release+/renew → перезапит IP.
- APIPA `169.254.x.x` = немає DHCP.
- Кабель: різні рівні → прямий; однакові → кросовий.
- ARP: broadcast-запит → unicast-відповідь → запис у таблицю.
- Керований switch (STP) гасить петлю; некерований падає за ~10–15 хв.
- Між мережами — роутер + gateway на кожному вузлі; Cisco-інтерфейси треба `no shutdown`.
- NAT підміняє сіру IP на білу; LAN-мережу варто змінювати з дефолтної.
