# Edda — Stack

> Generic project artifact. Describes **what Edda is built with** and the **decisions** behind it. For structure see [`architecture.md`](./architecture.md); for scope see [`goals.md`](./goals.md).
> Versions reflect the current (2026) landscape, web-verified at authoring time.

## Web stack (today)

| Layer | Choice | Notes / why |
|---|---|---|
| **Language** | TypeScript **^6.0** (`strict`, `noUncheckedIndexedAccess`, `moduleResolution:"bundler"`) | All contracts are TS; strictest practical settings. |
| **UI framework** | **Vue ^3.5** (Composition API, `<script setup>`) | Prototype is Vue 3; the renderer is framework-agnostic by contract, so framework choice is low-stakes — keep it. |
| **Build** | **Vite ^8** (Rolldown), fallback Vite 7 | Code-split dynamic `import()` *is* the plugin install mechanism. |
| **Routing** | **Vue Router ^5** (typed/file-based in core) | Typed `/reader/:sourceId/:bookId/:mediaType`. |
| **State** | **Pinia ^3** (UI) + **Pinia Colada** (read-side server cache) | The sync **outbox is not** a query lib's job — it is core code. |
| **Styling** | **Tailwind ^4** (Oxide) — app chrome only | Book typography lives in readium-css inside the navigator iframe. |
| **EPUB engine** | **foliate-js** (MIT, vendored at a pinned git SHA) | Parses + renders raw EPUB bytes **client-side from OPFS** — the offline-first need Readium's *web* navigator does not meet. One engine also covers EPUB→FB2/MOBI/CBZ later. |
| **EPUB model** | **`@readium/shared` ^2.2** | Locator/Publication vocabulary; a tested **CFI↔Locator adapter** maps foliate's CFI/DOM-ranges into it. |
| **PDF engine** | **pdfjs-dist ^6.1** (Apache-2.0) | Text layer for `page=/coords` locators, range streaming. |
| **Byte storage** | **OPFS** (web platform, no dep) | Stream downloads to disk; range reads via `File.slice`; sync access handle in a Worker for hot writes. |
| **Structured storage** | **Dexie ^4.4** (Apache-2.0) | Typed tables + safe migrations for registry, metadata, outbox. |
| **PWA / SW** | **vite-plugin-pwa ^1.3** (`injectManifest`) | Precache shell only; runtime-cache plugin chunks; **book bytes bypass the SW**. |
| **Sync** | **Custom sync engine** (Dexie-backed outbox + furthest-wins) driving a per-connector **`ProgressSyncStrategy`** | No library does furthest-progression-wins against a server we don't own; sync mechanics vary per server, so the engine is core and the mechanism is a connector-provided strategy. |
| **Plugin loading** | Native ES **`dynamic import()`** + Vite splitting; **semver ^7** for host-API gating | Lazy chunk = "install"; persist the enabled-ID set, not paths. |
| **Package manager / repo** | **pnpm ^10**; single-package now, workspaces when the native target lands | The `platform/` boundary is the natural future seam. |

## Native stack (later, separate codebase)

A true native client, sharing only the specification layer (see [`architecture.md` → Cross-platform reuse contract](./architecture.md#cross-platform-reuse-contract)) — **not Capacitor**.

- **UI:** Kotlin + Jetpack Compose (Android-first).
- **Rendering:** Readium Kotlin toolkit (renders + parses EPUB/PDF natively, no server needed; emits the same Locator shape).
- **Connector:** a Kotlin Komga REST client implementing the same connector + `ProgressSyncStrategy` protocol.
- **Sync/storage:** the same sync engine semantics + Locator protocol over native filesystem + SQLite.

## Licensing posture

The entire primary web stack is permissive (MIT / Apache-2.0 / BSD-3 / ISC) — no copyleft. The notable trap, **`mupdf-wasm`, is AGPL-3.0 and deliberately avoided** (its network-use copyleft would be viral for a self-hostable app); `pdfjs-dist` (Apache-2.0) is used instead.

## Decisions (ADR-lite)

| # | Decision | Why |
|---|---|---|
| ADR-001 | **Keep Vue 3** for the web shell | Renderer is framework-agnostic by contract (mounts a raw `HTMLElement`); prototype already Vue; switching = cost, no gain. The one rule: wrap `Publication`/`Navigator`/`Session` in `markRaw()` so reactivity never corrupts the imperative renderer. |
| ADR-002 | **foliate-js** for EPUB, not Readium's web navigator | Readium-web needs a server-built manifest; Edda is offline-first and must parse client-side from OPFS. foliate parses raw bytes in-browser. Cost accepted: vendor a pinned SHA (no real npm release), own a CFI↔Locator adapter. |
| ADR-003 | **`@readium/shared` for the model** + adapter | Keeps the Readium-aligned contract (and native-toolkit compatibility) even though rendering is foliate. |
| ADR-004 | **pdf.js** for PDF; **avoid mupdf-wasm** | mupdf-wasm is AGPL → viral for a self-hostable app. pdf.js is Apache-2.0 and battle-tested. |
| ADR-005 | **OPFS for bytes, Dexie for structure**; bytes bypass the SW | Correct streaming/range behaviour; Workbox cannot cache a `206` correctly. |
| ADR-006 | **Native = Kotlin/Compose + Readium-Kotlin, not Capacitor** | A real native client was a requirement, not "web on phone." Reuse is the spec layer, not UI code. |
| ADR-007 | **Komga first, fully using its native REST** (OPDS a later fallback) | Komga's REST has more modern reading (streaming/PSE) and progress sync than OPDS; build to Komga's full API rather than the OPDS lowest-common-denominator. OPDS arrives later as the generic fallback. |
| ADR-008 | **Custom sync engine**, not a query library | No library does furthest-progression-wins against a server we don't own; query libs cover the read side only. |
| ADR-011 | **Progress sync is a connector-scoped Strategy** | Sync mechanics depend on server capabilities (Komga REST vs OPDS v2 vs none). A `ProgressSyncStrategy` (Strategy pattern) is provided per connector and gated by `progressSync`; the **core sync engine is the context** (outbox, scheduling, furthest-wins). Keeps connectors free of queue/cache ownership while making the server-specific part swappable, and the strategy interface is part of the shared spec the native client reuses. |
| ADR-009 | **Host Bridge async from day one** | Same plugin code runs in-process now and behind a sandbox proxy later. |
| ADR-010 | **First-party plugins only for now** | No third-party authoring/SDK/marketplace/remote execution in scope; the contract is shaped to allow it later but it is out of scope ([`goals.md`](./goals.md)). |
| ADR-013 | **Reader origin isolation** — the foliate EPUB engine runs inside a cross-origin `<iframe>` served from a separate, configurable origin (`VITE_READER_ORIGIN`), so book content physically cannot read the app origin's credentials | **Why a separate origin?** Four in-app sanitization approaches (ADR-012) each failed a Gate-2 security review — the structural defect is that any in-app sanitizer must perfectly mirror foliate's internal resource routing AND the browser's MIME handling; one miss leaks credentials. A Playwright spike compared three candidates: (1) same origin (the bug — creds readable); (2) opaque `sandbox="allow-scripts"` frame on the app origin — isolates creds, but foliate's nested spine iframes inherit the opaque parent, so `contentDocument` returns `null` and pagination breaks; (3) **separate served origin** — isolates creds AND keeps `contentDocument` accessible AND gives the bridge a real `event.origin` to validate. Only option (3) satisfies both constraints. **Bridge design:** the app creates a `MessageChannel`, embeds the reader `<iframe>` (no `sandbox` attribute — the cross-origin URL is the isolation), and posts the init handshake with `targetOrigin = READER_ORIGIN` (never `*`) transferring one `MessagePort`. After the handshake the app listens for frame events **only over that capability `MessagePort`** — there is NO app-side window `message` listener. This matters because a book script is same-origin to the reader origin and could `window.top.postMessage` a forged `locatorChanged`/`error` that an `origin === READER_ORIGIN` check on a window listener would wave through. The port-only design closes that seam: book content cannot reach the port, which was handed to the frame alone. **Byte transfer:** the app fetches `connector.content()` (credentials stay on the app origin) and transfers the book `ArrayBuffer` as a Transferable (zero-copy, ADR-005 preserved — bytes bridged, never SW-intercepted). The frame builds the foliate publication in-frame; credentials never cross. **Fail-closed:** if `VITE_READER_ORIGIN` is unset, or equals the app origin, the navigator proxy throws and renders nothing — there is no same-origin fallback. Dev/e2e auto-configure a second port (`:5174`) so the whole pipeline is testable in CI. **Deletes ADR-012's mechanism** (`content-security.ts` and the CSP-injecting `loadText` seam) — with the engine on a credential-free origin there is nothing to sanitize. **Dev/e2e default:** `VITE_READER_ORIGIN=http://localhost:5174` (auto-injected by Vite when unset in dev mode). **Prod:** operator sets a sibling port or `reader.`-subdomain; see README "Reader origin". |
| ADR-012 *(superseded by ADR-013)* | **SUPERSEDED by ADR-013 (reader origin isolation). Retained as historical record.** **Framed EPUB content is neutralised by parse-and-strip + a defence-in-depth per-document CSP** (the reader is the first screen to mount untrusted book HTML/JS/SVG) | foliate renders each spine document in an `<iframe sandbox="allow-same-origin allow-scripts">` on the **app origin**, where `edda.creds.<id>` lives in `localStorage`. `allow-scripts` is only foliate's workaround for a WebKit event-delivery bug (#218086) and **cannot be removed** without breaking Safari/iOS; foliate injects no script of its own and drives pagination from the parent via `contentDocument`. **Threat:** a crafted EPUB's own `<script>`, inline `on*=` handler, or `javascript:`/`data:text/html` URL could read `window.parent.localStorage` and exfiltrate creds. **Decision:** at parse time, in the format handler's shared `loadText` (`book-loader.ts`) — the single seam BOTH the headless parse and the render path (`view.open(book)` with a pre-built book, not `view.open(file)`) read through — neutralise **every framed content document, media-type-independently**, before it becomes a `blob:` URL: (1) **parse-and-strip** (primary, **forgery-proof media-type dispatch**) — foliate decides "load into the scripting iframe — and HTML/XML-parse, so script-execute" by the manifest **media-type**, not the root element: its `loadReplaced` parse-branch frames exactly `application/xhtml+xml`/`text/html`/`image/svg+xml` (epub.js:814, gated by `loadItem`:777-781), *including* the malformed/un-namespaced `application/xhtml+xml`→`text/html` downgrade (epub.js:817-822). So the gate decides skip-vs-sanitise on that **same signal**: it **sanitises iff the resource's media-type is one foliate frames** (the loader threads it from the OPF `href→media-type` manifest map it pre-parses — `book-loader.ts`) and passes everything else through byte-for-byte. Because the skip decision and foliate's frame decision read the **same media-type**, a spine document **cannot dodge the sanitiser by forging its root element** (a forged `<package>`/`<svg>`/`<section>` root declared `application/xhtml+xml` is still sanitised). The root element sub-selects **only** WHICH sanitiser runs — an `<svg>` root → the SVG sanitiser, otherwise the (X)HTML sanitiser — never *whether* to sanitise. (When no media-type is supplied — a caller exercising a sanitiser in isolation, never the render path — the gate falls back to a default-deny structural dispatch: sanitise unless non-markup or a closed control root; that fallback is unreachable in production, so it can't be a bypass vector.) The (X)HTML sanitiser removes every `<script>` element (HTML *and* SVG, any namespace/casing/position), every inline `on*` attribute, every `javascript:`/`data:text/html`/`vbscript:` URL in `href`/`xlink:href`/`src`, and every `<meta http-equiv="refresh">` to a `javascript:`/`data:` URL (L2), and re-serialises (`XMLSerializer`/`outerHTML`) preserving namespaces + doctype so foliate still paginates and body CFIs stay stable; (2) **meta-CSP** (defence-in-depth, (X)HTML only) — inject `default-src 'none'; script-src 'none'; connect-src 'none'; base-uri 'none'; form-action 'none'; img-src data: blob:; style-src 'unsafe-inline' blob:; font-src blob: data:; media-src blob: data:` as the first `<head>` child, which also denies `connect-src` egress for anything the strip misses. The byte-for-byte passthrough is therefore everything foliate does **not** frame as an executable document: the CSS/JS sub-resources, and the strict-XML control vocabulary it reads via `#loadXML` — the OCF files (`container`/`encryption`/`signatures`/`manifest`/`metadata`), the OPF `package`, the `ncx`, Media-Overlay `smil`, and the Apple/Kobo `display_options` render-hints doc — which carry non-iframe-able media-types (or, for the OCF/OPF docs foliate loads by hardcoded path, no manifest media-type at all). `#loadXML` (epub.js:942) THROWS on any XML parse error, so these MUST stay byte-identical or the book won't open (e.g. corrupting `display_options` would fail to open any EPUB shipping it). The control-vocabulary *root* set is now consulted only by the no-media-type structural fallback, never the render path, so it can no longer be the bypass surface. Parent-side pagination is unaffected (a child CSP never governs the parent). **Why strip, not CSP alone:** a meta-CSP cannot govern an **SVG-root spine Content Document** (no `<head>`; valid in a *reflowable* EPUB, so fixed-layout is not required) nor a `<script>` placed *before* the first `<head>` — both bypassed a meta-CSP-only design; the parse-based strip is media-type- and position-independent (and decodes entity-obfuscated URLs a regex would miss), and is the SOLE defence for SVG. **Proven both ways** by the reader e2e (real Chromium): a benign EPUB paginates; the probe EPUB's seven spine docs (inline `<script>`, a `<script>` before `<head>`, inline `on*`, the two **H2** non-`<html>`/`<svg>`-root fragments, and the two forged-control-vocabulary-root `<package>` fragments — declared `application/xhtml+xml` and `text/html`) render through foliate's real path without setting any `localStorage` key or reaching the attacker origin; and an SVG-root doc (H1), a `<section>`-root `text/html` doc (H2), and a forged `<package>`-root doc (HIGH-1), each framed exactly as foliate frames it and hardened through the real media-type-keyed seam, **run + exfiltrate when raw but do neither once hardened** (no marker key, zero requests to the attacker origin), while `javascript:`/`data:` URL + scripted meta-refresh neutralisation, the per-control-root forgery cases, and the control-vocabulary byte-identity are covered exhaustively by the `content-security.test.ts` unit suite. **Control-root forgery (the former accepted residual) — now CLOSED:** a spine document forging a control-vocabulary root (`<package>`/`<ncx>`/…) was an accepted residual while the gate keyed passthrough on the root element; it is **closed** now that the gate keys on the manifest media-type foliate frames by — a forged-root spine doc carries an iframe-able media-type, so it is sanitised regardless of root, and the discriminator cannot be forged because the skip decision and foliate's frame decision read the **same field** (proven by reader e2e Test E + the per-control-root `content-security.test.ts` cases). **Remaining residual risk:** `'unsafe-inline'` styles remain (CSS-only data exfil — network channels are shut by `connect-src`/`img-src`/`font-src` — out of scope); a resource foliate frames *without* routing through `loadText` (a manifest media-type its exact `loadReplaced` match list does not recognise → it blobs the raw bytes) is outside this seam's reach — a foliate-internal limitation, **not** the root-forgery class, and closing it would require patching vendored foliate or a credential-free origin (deferred); and this is in-app hardening rather than a separate credential-free origin (the stronger, larger-lift option deferred). The earlier SVG-root (**H1**), pre-`<head>` script (**M1**), non-`<html>`/`<svg>`-root content-document (**H2** — a `<body>`/`<section>`/`<math>`/bare-`<script>` doc), and forged-control-vocabulary-root (**HIGH-1** — a `<package>`/etc. spine doc declared `application/xhtml+xml`/`text/html`) bypasses are now **closed** by keying the skip-vs-sanitise decision on the manifest **media-type foliate frames by**, not the root element. This makes the whole classification class **non-recurring by construction**: the skip decision and foliate's frame decision read the same signal, so no root shape — foreseen or not — can split them, and every document foliate frames is sanitised. |
