# System Architecture (ARCHITECTURE.md)

This document describes the design and architectural patterns of the software engineering loop and the core game/simulation engine.

---

## 1. Engine Architecture Overview

The engine is built on a unidirectional data flow pattern, similar to Elm or Redux. This pattern ensures **determinism, testability, and state reproducibility**, which are critical for agentic automation and human verification.

```
       ┌────────────────────────┐
       │       GameState        │◀────────────────────────┐
       └────────────────────────┘                         │
                    │                                     │
                    │ (read by)                           │
                    ▼                                     │
       ┌────────────────────────┐                         │
       │        Renderer        │                         │
       └────────────────────────┘                         │
                    │                                     │
            (triggers/produces)                           │ (updates)
                    ▼                                     │
       ┌────────────────────────┐                         │
       │         Event          │                         │
       └────────────────────────┘                         │
                    │                                     │
                    │ (mapped/parsed to)                  │
                    ▼                                     │
       ┌────────────────────────┐      ┌───────────┐      │
       │         Action         │ ───▶ │  Reducer  │ ─────┘
       └────────────────────────┘      └───────────┘
```

## 2. Core Architectural Components

### 1. GameState
The single, immutable source of truth for the entire application. It is a plain JavaScript object representing the state of the ship, resources, discovered star systems, active probes, and history at any given moment.

* **Example Structure**:
  ```javascript
  const initialGameState = {
    resources: {
      industry: 150,
      science: 80
    },
    ship: {
      hullIntegrity: 100, // max 100
      fuelCapacity: 80,   // max 100
      sensorRange: 1      // max 5
    },
    discoveredSystems: [
      { id: "sol", name: "Sol", planetsRevealed: true }
    ],
    probes: [
      { id: "p1", targetSystem: "alpha-centauri", etaTicks: 3 }
    ],
    achievements: {
      experiencedCategories: ["Deep Space", "Star System Arrival"]
    }
  };
  ```

### 2. Event
External or system-driven raw inputs that represent "what happened" in the outside world (e.g., user interactions, ticks, network calls). Events do not directly modify state.

* **Examples**:
  * `ClickUpgradeButtonEvent` (payload: `{ stat: 'sensorRange' }`)
  * `LaunchProbeRequestedEvent` (payload: `{ systemId: 'alpha-centauri' }`)
  * `EngineTickEvent`

### 3. Action
A serialized representation of a state-changing intent. Actions are generated by processing raw events and represent clear, well-formed commands containing a type and an optional payload.

* **Examples**:
  ```javascript
  { type: 'UPGRADE_SHIP_STAT', payload: { stat: 'sensorRange', cost: 50 } }
  { type: 'LAUNCH_PROBE', payload: { targetSystemId: 'alpha-centauri', cost: 20 } }
  { type: 'TRIGGER_GAME_EVENT', payload: { category: 'Distress Signal', description: 'SOS received...' } }
  ```

### 4. Reducer
A pure, side-effect-free function that accepts the current `GameState` and an `Action`, and returns a brand-new `GameState`. Reducers are fully deterministic and make debugging, state travel, and unit testing trivial.

* **Pattern**:
  ```javascript
  function reducer(state, action) {
    switch (action.type) {
      case 'UPGRADE_SHIP_STAT': {
        const { stat, cost } = action.payload;
        if (state.resources.industry < cost) return state; // invalid
        return {
          ...state,
          resources: { ...state.resources, industry: state.resources.industry - cost },
          ship: { ...state.ship, [stat]: state.ship[stat] + 1 }
        };
      }
      case 'LAUNCH_PROBE': {
        const { targetSystemId, cost } = action.payload;
        if (state.resources.science < cost) return state;
        return {
          ...state,
          resources: { ...state.resources, science: state.resources.science - cost },
          probes: [...state.probes, { id: generateId(), targetSystem: targetSystemId, etaTicks: 3 }]
        };
      }
      default:
        return state;
    }
  }
  ```

### 5. Renderer
The presentation layer. The renderer reads the current `GameState` and projects it onto the user interface (CLI console, canvas, or Web DOM). It is strictly read-only and is decoupled from state-transition logic.

## 3. Data Flow Example: Launching a Probe

To demonstrate the full unidirectional cycle:
1. **User Action**: The player clicks "Launch Probe to Alpha Centauri".
2. **Event Dispatch**: The system emits an `Event` containing the player's interaction details.
3. **Action Mapping**: The event is mapped to the action `{ type: 'LAUNCH_PROBE', payload: { targetSystemId: 'alpha-centauri', cost: 20 } }`.
4. **Reduction**: The `Reducer` subtracts `20` from the `science` resource and appends the new probe to the `probes` array in `GameState`.
5. **Render Update**: The `Renderer` senses the state change and redraws the UI, showing the updated resource counts and starting a visual countdown timer for the probe.
