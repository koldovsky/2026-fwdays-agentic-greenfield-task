# Risk Register — «Поливайко» (MVP)

> Known risks and limitations with mitigation and status. Stated as plainly as
> the successes. Owner = orchestrator unless noted. Status as of 2026-06-30
> (Europe/Kiev).

| ID | Risk / limitation | Likelihood | Impact | Mitigation | Owner / Status |
|---|---|---|---|---|---|
| R-01 | **Cyrillic display falls back to Mulish.** Quicksand (display) and Spline Sans Mono (meta/mono) ship **latin-only** on Google Fonts — no Cyrillic subset. Ukrainian headings/meta render in the Mulish fallback, not the Latin display face. | High (always, for UA copy) | Low — text is fully legible; only the decorative display face is not applied to Cyrillic | By design: the `@theme` font stacks fall through to Cyrillic-capable **Mulish** before the system sans, so all glyphs stay on a webfont (`app/layout.tsx`, `app/globals.css`, design D2). Documented, accepted. | Accepted / documented |
| R-02 | **Single-user, no auth (NFR-SEC-01).** No credentials, sessions, or access control — anyone with local access to the app/SQLite file sees all data. | Certain (by scope) | Low for a local single-user demo; would be High if deployed multi-user | Intentional MVP scope (TC-04, BC-02, Q6, ADR-0001 drops Better Auth). NFR-SEC-02 defines the policy *if/when* multi-user (FR-SHELL-05) is built. | Accepted / by design |
| R-03 | **No cloud deploy in MVP (ADR-0001).** SQLite + local run only; deploy-gated NFRs (PERF-03 p95/Lighthouse, COMPAT-03 uptime) cannot be measured. | Certain (by scope) | None for MVP acceptance; deferred | Recorded in ADR-0001; PERF-03 / COMPAT-03 are **Future**. A follow-up ADR swaps SQLite→Postgres when deploy becomes MVP+1 (Drizzle keeps schema portable). | Accepted / Future |
| R-04 | **Cross-browser only verified on Chromium (NFR-COMPAT-02).** Playwright runs a single `chromium` project; Firefox/Safari/Edge not run in CI. | Medium | Low — standard Next.js/Recharts/CSS; no browser-specific APIs | Manual cross-browser spot-check is part of release (Phase 7); the manual test plan is Chrome-executable. No known incompatibility. | Open — manual check at release |
| R-05 | **NFR-PERF-01/02 not asserted by a CI millisecond timer.** The <300 ms mutation / <500 ms chart budgets are observed locally, not gated. | Medium | Low for the realistic dataset (≤20 plants, ≤365 pts); pure series seam + `force-dynamic` revalidate | Series tests carry 365+ points uncapped; no perceptible lag in e2e/demo runs. Treated as met by construction. | Accepted / observed |
| R-06 | **Demo stills predate the AA contrast token darkening.** Some recorded `.png` frames were captured before the final forest/status token darkening for WCAG 2.1 AA (NFR-A11Y-02); they are a legibility-only difference, not a behavior difference. The small gray «.jpg» placeholder filename captions over sage stripes remain low-contrast. | Medium | Low — clips remain legible (vision 6/6); the *shipped* theme is the darkened one, gated by `check:a11y` (0 serious/critical) | Re-record is optional; the placeholder captions are decorative/non-essential. AA contrast is enforced on the live app by `npm run check:a11y`, not by the stills. | Accepted / noted; optional re-record |
| R-07 | **Transitive PostCSS XSS advisory (GHSA-qx2v-qp2m-jg93, moderate).** Reaches us only via `next@16.2.9`'s pinned `node_modules/next/node_modules/postcss` (<8.5.10); our own top-level `@tailwindcss/postcss` already resolves to a patched 8.5.x. | Low | Low — not reachable: no user-controlled CSS stringify path | Documented in archived `add-watering`/`add-plants` design + review-triage (ACCEPTED). Revisit and bump when a Next.js patch depends on PostCSS ≥8.5.10. | Accepted / transitive |
| R-08 | **Eval field-key vs contract divergence.** Several error-clarity cases surface messages under keys like `inlineMessageForName` instead of the spec'd `fieldErrors.<field>` shape. | Low | Very low — the user-facing Ukrainian message is correct and inline; this is an internal payload-shape nit | Eval cases still **pass** (deducted a few points, see `eval-report.md` per-case notes). Reconcile the result shape to the shared `ActionResult` contract in a follow-up if a consumer needs it. | Open — cosmetic; tracked |
| R-09 | **Recording stills capture end-states, not every step.** A single settled frame can't show intermediate flows (e.g. the 3→1 decrement, the add/edit steps). | Certain | Low — flows are proven by asserted e2e + the `.webm`, not the frame | Vision-report notes the caveat per clip; e2e tests assert the transitions. Capture before/after frames if a customer needs step-by-step stills. | Accepted / documented |
| R-10 | **Cross-slice module overlap** in `lib/i18n/` (7 slices), `lib/theme/` (2), `lib/plants/` (3). | Low | Low — expected for shared i18n/theme; no scope drift found | `check:trajectory` flags these as in-scope **warnings** (PASS overall); reviewed, expected for cross-cutting copy/tokens. | Accepted / reviewed |

## Out of scope for MVP (not risks — explicit deferrals)

Photos (FR-PLANT-09), search/filter (FR-PLANT-10), extra growth metrics
(FR-GROWTH-06), water amount (FR-WATER-06), OS notifications (FR-WATER-07 /
FR-REM-08), chart granularity/insights (FR-CHART-05/06), export/import
(FR-SHELL-04), multi-user (FR-SHELL-05), English/other UI (NFR-LOC-02) — all
**Future** per `docs/requirements.md` and TC-06.
