# QA artifacts (the deterministic harness layer)

Generated, diff-safe evidence produced by the gate scripts in
[`scripts/`](../../scripts/). These files are the machine-checkable half of the
engineering trail: they prove only what code and git can show. Judgment calls
(does a test really exercise the behavior? was a review substantive? was the code
written test-first?) are graded later by the checker/judge and the eval suites, not
here. See each script's `--help` and the honesty boundary in `trajectory.md`.

## Files

| Path | Produced by | What it is |
| --- | --- | --- |
| `traceability.md` | `scripts/check-traceability` | Every spec-claimed requirement mapped to its `@trace <ID>` test; **GAP** = claimed but untested. **Generated — do not hand-edit.** |
| `trajectory.md` | `scripts/check-trajectory` | Per-slice commits/trailers, touched code paths, cross-slice overlap. **Generated — do not hand-edit.** |
| `coverage-floor.txt` | `scripts/gate-slice --bump-floor` | Backend coverage ratchet floor (percent). May rise, never silently fall. |
| `eval/baseline.json` | `scripts/check-eval-ratchet --promote` | Coach-eval score floor. Absent until the coach slice (006). |
| `eval/latest.json` | the eval runner (slice 006) | Newest coach-eval scores, compared against the baseline. |
| `reviews/<slice>.md` | the Checker (a human/agent pass) | Review evidence for a slice (see convention below). Not generated. |

## Regenerating

The pre-commit hook regenerates and self-stages `traceability.md` and
`trajectory.md`. To do it by hand:

```
python scripts/check-traceability --write
python scripts/check-trajectory  --write
```

CI (see [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml)) treats the two
files differently:

- `traceability.md` is a pure function of the working tree (requirements + specs +
  tests), so CI runs `check-traceability --check-fresh` and a **stale committed matrix
  fails CI**.
- `trajectory.md` depends on git history *including its own commit*, so a committed
  snapshot necessarily lags by exactly that commit and cannot be freshness-gated. CI
  instead runs `check-trajectory` in enforce mode: it re-derives from the full history
  and fails only on a real **process violation**. The committed `trajectory.md` is a
  best-effort snapshot (regenerated by the pre-commit hook) kept for the trail.

## Coverage ratchet

`scripts/gate-slice` measures backend coverage of the `app` package (with
`RUN_DB_TESTS=1`) and fails if it drops below `coverage-floor.txt`. Raise the floor
only deliberately, when coverage has genuinely improved:

```
python scripts/gate-slice --bump-floor    # writes floor(measured) to the floor file
```

## Review-evidence convention (for `check-trajectory`)

A slice is "done" when its spec `Status:` is `done`/`shipped` **or** every
requirement it claims is `shipped` in [`docs/requirements.md`](../requirements.md).
Before a slice may be marked done, the Checker commits review evidence at
`docs/qa/reviews/<slice>.md` (e.g. `reviews/001.md`). `check-trajectory` treats it as
**clean** when it contains a line:

```
Result: pass        # or: clean / approved
```

and no `Result: fail|blocked|reject` and no `Blocker: open` line. A slice marked
done without clean evidence is a hard process violation. This encodes
maker != checker != judge in a way git can verify: the evidence must exist and be
clean *before* the done state.

## Eval ratchet (built ahead of the coach slice)

`scripts/check-eval-ratchet` is a no-op until `eval/baseline.json` exists. When the
coach slice (006) lands its eval cases, its runner writes `eval/latest.json` and a
judge promotes an accepted run to the baseline with
`python scripts/check-eval-ratchet --promote`. Thereafter each dimension's score may
tighten but never silently loosen.
