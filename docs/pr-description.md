## Які практики Agentic Engineering застосовано

### Контекст-інженерія

[`AGENTS.md`](../AGENTS.md) is the durable, hand-authored cross-cutting
rulebook every agent in this project reads first: stack lock, module
conventions (`lib/` must stay framework-free — `TC-PURE-01`), non-negotiable
correctness rules (error surface, locale formatting, honesty about stale
dates, brand tone), and the per-slice loop itself. Static-vs-dynamic context
is split deliberately: durable rules live in `AGENTS.md`; everything
slice-specific lives in OpenSpec change folders that get archived once done,
so `AGENTS.md` never bloats. `docs/current-state.md` is the dynamic handoff
log, updated at every milestone per a standing rule in `AGENTS.md` itself
("maintain this automatically... without being asked").

### Цикли (loop engineering) — не покроковий промптинг

A repeatable, hand-authored per-slice loop drove all 8 capability slices:
propose (OpenSpec change, validated `--strict` before any code) → build
tests-first (RED, then GREEN) → two-checker review → archive → commit with
`Slice:`/`Refs:` trailers. The loop itself, its gates, and its agent roles
are **explicitly not generated by a turnkey framework** — see
[ADR-0003](../docs/adr/ADR-0003-prior-art-reuse-boundary.md), which records
exactly what was reused (mechanisms: OpenSpec's CLI, git hooks, CI shape) vs.
authored (the maker/checker split, the gates, what "good" means for this
specific app). [CHECKLIST.md](../CHECKLIST.md)'s G0–G7 gates are my own,
project-tuned — not a copied template.

### Maker ≠ checker

Every slice was built by one role (`kurs-maker`, per
[`.claude/agents/kurs-maker.md`](../.claude/agents/kurs-maker.md)) and
reviewed by two independent roles that never built it:
`kurs-reviewer` (spec compliance + correctness) and `kurs-eval-judge`
(qualitative grading — tone, clarity, honesty). This ran twice: once per
slice (8 times, `docs/qa/review-findings.md` + `docs/qa/eval-report.md`,
one section each) and once globally before release (Stage 10 — both
checkers re-read the **entire** app cold, explicitly instructed not to
trust the maker's own self-review note, `docs/qa/global-review.md`). The
global pass caught a real cross-slice defect no per-slice review could see:
the currency converter silently rounded a rate to fewer decimals than the
rest of the app showed for the same currency — fixed in
[`lib/currency/formatRate.ts`](../lib/currency/formatRate.ts), live-verified
in a real browser, not just asserted by a test.

### Верифікація — тести, evals, перевірки, не «здається працює»

- **Unit + integration:** 122 Vitest tests, every `lib/` module tested
  tests-first (`@trace FR-x` annotations link each test back to a numbered
  requirement), plus one integration test
  ([`convertFlow.integration.test.ts`](../lib/currency/convertFlow.integration.test.ts))
  composing real modules end-to-end without mocking.
- **E2E + accessibility:** 14 Playwright tests against a real dev server and
  **live NBU data** — core user flow, responsive breakpoints (measuring
  actual computed CSS grid tracks, not screenshot-eyeballing), and
  `@axe-core/playwright` WCAG 2 A+AA scans in both light and dark themes.
  This pass found and fixed three real accessibility defects (two contrast
  failures, one missing accessible name) that eight clean manual reviews
  had missed — see `docs/qa/automated-verification-latest.md`.
- **Qualitative evals:** `evals/cases/*.eval.ts`, one rubric per capability's
  qualitative surface (Ukrainian tone, no exclamation marks, error clarity),
  graded by the `kurs-eval-judge` checker role — every case PASS, 9/9
  scopes (8 slices + 1 global pass) reviewed in
  [`docs/qa/acceptance-report.md`](../docs/qa/acceptance-report.md).
- **Traceability:** `scripts/check-traceability.mjs` (hand-authored) gates
  every commit on every MVP requirement being cited in a spec; a richer
  human-readable traceability matrix
  ([`docs/qa/traceability-matrix.md`](../docs/qa/traceability-matrix.md))
  traces every one of the 25 MVP + 1 Future requirement all the way to
  implementation, test, and e2e/eval evidence.

### Специфікації наперед (SDD)

Every capability was specified in OpenSpec (`openspec/specs/<capability>/spec.md`)
*before* any code was written, validated `openspec validate --strict` as a
pre-commit gate. Each slice's actual change went through its own change
folder (`proposal.md`, `design.md`, `tasks.md`) before implementation
started, then archived once the two-checker review was clean.

### Інструменти та MCP

Claude Code as the primary agent harness; the project's own
`.claude/agents/{kurs-maker,kurs-reviewer,kurs-eval-judge}.md` and
`.claude/commands/{propose-slice,review-slice}.md` define the loop. Real
browser verification throughout (not just DOM assertions) via the
Claude-in-Chrome MCP tool — used to catch a real bug (a React duplicate-key
collision on currency switch) and to visually confirm contrast/theming fixes
in both light and dark mode. Playwright + `@axe-core/playwright` for the
automated e2e/accessibility layer. No third-party PR-review service is part
of the engineering loop itself — maker≠checker separation is demonstrated
entirely by this project's own agents (CodeRabbit reviews the PR
afterward, as a mentor pass, not as part of the build loop).

### Що вирішував я, а що — агент

I set scope, approved the two project checkpoints (product framing, the
capability plan), made the brand/voice call (calm, Ukrainian-first, no
exclamation marks — `BC-BRAND-01`), and explicitly directed each stage
("start trend-hint", "let's make Stage 8", etc.) one at a time rather than
letting the agent run unsupervised end-to-end. The agent proposed each
spec's scenarios from the requirements, wrote every test and implementation
tests-first, ran both checker roles, found and fixed defects (including
ones I hadn't asked about — the Stage 10 precision bug, the Stage 8
accessibility failures), and maintained the handoff log
(`docs/current-state.md`) and full QA proof pack autonomously per the
standing rules in `AGENTS.md`.
