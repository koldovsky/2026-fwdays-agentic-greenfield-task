# Specs - the traceability anchor

Each meaningful feature is specified **before** code. Since adopting OpenSpec, the detailed contract
(GIVEN/WHEN/THEN scenarios, validated by `openspec validate --all --strict`) lives in
[`openspec/`](../../openspec/); the files **here** are thin anchor files that keep the deterministic
Python traceability harness working.

## What lives where

| Concern | Home |
| --- | --- |
| Requirement text (the source of truth) | [`docs/requirements.md`](../requirements.md) - stable FR/NFR/TC/BC ids |
| Detailed contract (proposal, design, tasks, scenarios) | `openspec/changes/<id>/` -> archived to `openspec/specs/<capability>/spec.md` |
| Traceability anchor (`NNN-*.md`) | **this folder** - problem + `Requirements covered` ids + link to the OpenSpec change |
| Requirement -> `@trace` test matrix | [`docs/qa/traceability.md`](../qa/traceability.md), generated by `scripts/check-traceability` |

Why the split: `scripts/check-traceability` walks `docs/specs/NNN-*.md` for each slice's
`Requirements covered` / `Out of scope` ids and maps them to `@trace <ID>` tests. Keeping a thin
`NNN-*.md` per slice means that gate logic is **unchanged** while OpenSpec holds the contract. See the
full rationale under "Decision" in [`openspec/README.md`](../../openspec/README.md).

## Flow (slices 002+)

New behavior starts as an OpenSpec change **before code** (the `brainstorming` skill still governs
idea -> approved design):

1. `openspec new change <kebab-name>`; write `proposal.md`, `design.md`, `tasks.md`, and the
   `specs/<capability>/spec.md` deltas (each `### Requirement:` names its FR/NFR id; each has a
   `#### Scenario:` in GIVEN/WHEN/THEN form).
2. Owner ratifies; `openspec validate <change> --strict` passes.
3. Add the thin `docs/specs/NNN-<slug>.md` anchor here (see `001-auth-email.md` for the shape:
   status, problem, `Requirements covered`, `Out of scope`, and a `Contract (OpenSpec)` link).
4. Implement to the contract, driving `scripts/verify.*`; add `@trace <ID>` docstrings so
   `check-traceability` turns GAP into COVERED.
5. On Judge sign-off, `openspec archive <change>`.

## Slice 001 is retroactive

[`001-auth-email.md`](001-auth-email.md) predates OpenSpec, so it is a **full ratified spec** (kept
as the historical record) plus a `Contract (OpenSpec)` pointer to the change that recorded it
retroactively. Slices 002+ are thin anchors from the start because their contract is authored in
OpenSpec first.

[`TEMPLATE.md`](TEMPLATE.md) remains a valid starting shape for the anchor file's prose sections.
Specs are living documents and double as evidence of the engineering process.
