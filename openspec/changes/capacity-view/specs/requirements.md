# Specs: capacity-view

Вимоги з PRD v0.3 (capability `capacity-view`, FR-CAP-01..05). ID для трасування.

- **FR-CAP-01** Гістограма завантаженості: два рівні — агреговано по **ГРЦ** і
  розгорнуто по окремих **РЦ**.
- **FR-CAP-02** Вісь Y — % від потужності; лінія 100 % — межа; перевантаження
  > 100 % підсвічується червоним.
- **FR-CAP-03** Одиниця часу осі X відповідає горизонту: дні (3 тижні), тижні
  (3 місяці), місяці (рік).
- **FR-CAP-04** Наведення на стовпець → список операцій у цьому слоті з
  трудомісткістю та номером замовлення.
- **FR-CAP-05** KPI-рядок над гістограмою: середня завантаженість по всіх РЦ,
  кількість перевантажених слотів, кількість РЦ з нульовим завантаженням (простій).

## Технічне

- **TC-STACK-04** Графіки завантаженості РЦ: Recharts.
- Агрегація (бакети, % завантаження, KPI, дані тултипів) — чисті функції.

## Сценарії тестування

### Сценарій A — Одиниця осі X за горизонтом
```
pickUnit:
  горизонт ~3 тижні → 'day'
  горизонт ~3 місяці → 'week'
  горизонт ~рік → 'month'
```

### Сценарій B — % завантаження по ГРЦ і РЦ
```
Вхід: ГРЦ-1 з РЦ-1 і РЦ-2, фонд 480 хв/день кожен, 1 робочий день
  РЦ-1 used 240 хв, РЦ-2 used 480 хв
Очікування:
  рівень 'rc': РЦ-1 = 50 %, РЦ-2 = 100 %
  рівень 'group': ГРЦ-1 = (240+480)/(480+480) = 75 %
```

### Сценарій C — KPI (середнє, перевантаження, простій)
```
Вхід: РЦ-1 used 480/480 (100 %), РЦ-2 used 600/480 (>100 %, перевантаження),
  РЦ-3 used 0 (простій)
Очікування KPI:
  avgLoadPct = (480+600+0)/(480+480+480) × 100 ≈ 75 %
  overloadedSlots = 1 (РЦ-2)
  zeroLoadRcs = 1 (РЦ-3)
```

### Сценарій D — Тултип операцій
```
Наведення на стовпець (серія, бакет) → список операцій цього слоту з
opName, orderId, durationMin.
```
