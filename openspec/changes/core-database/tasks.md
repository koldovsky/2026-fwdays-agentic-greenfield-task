## 1. Setup and Project Configuration

- [ ] 1.1 Додати необхідні залежності (`drizzle-orm`, `@neondatabase/serverless` або `pg`) та dev-залежності (`drizzle-kit`, `@types/pg`) у `package.json`.
- [ ] 1.2 Створити файл конфігурації `drizzle.config.ts` у корені проекту для налаштування `drizzle-kit`.
- [ ] 1.3 Оновити `.env.example` та локальний `.env` змінними `DATABASE_URL` та `ENCRYPTION_KEY` (32-байтовий ключ у hex-форматі).

## 2. Ініціалізація клієнта бази даних

- [ ] 2.1 Реалізувати файл `db/index.ts` для підключення до бази даних з урахуванням специфіки Serverless (лінива ініціалізація та перевикористання з'єднання).

## 3. Опис схем таблиць Drizzle ORM

- [ ] 3.1 Створити файл `db/schema/users.ts` та визначити таблицю `users` з UUIDv4 як первинним ключем, полями для Telegram-бота (telegram_id як bigint, сумісний з JS string/BigInt; забезпечити перетворення на рядок перед серіалізацією JSON), CRM-інтеграції, телефонії та унікального api_key_hash (SHA-256).
- [ ] 3.2 Створити файл `db/schema/magic_links.ts` та визначити таблицю `magic_links` з UUIDv4 як первинним ключем та унікальним UUIDv4 токеном (встановити `onDelete: "cascade"` на зв'язку з `users.id`).
- [ ] 3.3 Створити файл `db/schema/sessions.ts` та визначити таблицю `sessions` з UUIDv4 як первинним ключем та унікальним UUIDv4 токеном сесії (встановити `onDelete: "cascade"` на зв'язку з `users.id`).
- [ ] 3.4 Створити файл `db/schema/subscriptions.ts` та визначити таблицю `subscriptions` (UUIDv4 як первинний ключ) із статусами підписки, платіжними токенами monobank, сумою (amount) та валютою (currency), а також полями ретраїв списань та invoice_id (встановити `onDelete: "cascade"` на зв'язку з `users.id`).
- [ ] 3.5 Створити файл `db/schema/conversions.ts` та визначити таблицю `conversions` (UUIDv4 як первинний ключ) для збереження записів конверсій з композитним індексом `idx_conversions_user_id_conversion_time` та індексом `idx_conversions_conversion_time` для очищення (встановити `onDelete: "cascade"` на зв'язку з `users.id`).
- [ ] 3.6 Створити файл `db/schema/index.ts` для об'єднання та експорту всіх таблиць схеми.

## 4. Утиліти шифрування та дешифрування

- [ ] 4.1 Реалізувати модуль шифрування `lib/crypto.ts` на базі алгоритму AES-256-GCM з використанням вбудованого модуля `crypto` в Node.js (з обов'язковою перевіркою, що 64-символьний hex-рядковий ключ `ENCRYPTION_KEY` при декодуванні становить рівно 32 байти, а також з обробкою `DecryptionFailedError` без витоку конфіденційних даних).
- [ ] 4.2 Створити unit-тести або тимчасовий тестовий скрипт для перевірки коректності шифрування та дешифрування даних.

## 5. Генерація міграцій та перевірка

- [ ] 5.1 Запустити генерацію міграцій (`npx drizzle-kit generate`) та перевірити згенеровані SQL-файли у директорії `db/migrations`.
- [ ] 5.2 Перевірити збірку проекту (`npm run build` або компиляцію TypeScript) на відсутність помилок типізації схеми та підключення бази даних.
