# Specs: material-check

Вимоги з PRD v0.3 (capability `material-check`, FR-MAT-01..03). ID для трасування.

- **FR-MAT-01** Таблиця дефіциту: матеріал, брутто-потреба, залишок, план
  надходжень, нетто-дефіцит, дата закриття дефіциту, заблоковані замовлення.
- **FR-MAT-02** Матеріали з критичним дефіцитом (без надходжень, що покривають)
  виносяться в окремий блок із попередженням.
- **FR-MAT-03** Ручне коригування залишків або плану надходжень → система одразу
  перераховує вплив на розклад (без повного перепланування).

## Сценарії тестування

### Сценарій A — Критичний дефіцит
```
Вхід: gross M = 10, залишок 0, надходжень немає
Очікування:
  computeMaterialCheck → deficits [M], critical [M], coverable []
  M.earliestCoverDate = null
```

### Сценарій B — Покривний дефіцит
```
Вхід: gross M = 10, залишок 0, дата споживання Jan10,
  надходження {M, Jan15, 10, confirmed}
Очікування:
  net-дефіцит = 10 (надходження після дати споживання не зменшує net)
  earliestCoverDate = Jan15 → coverable [M], critical []
```

### Сценарій C — Перерахунок при правці (FR-MAT-03)
```
Старт: критичний дефіцит M (без надходжень)
Правка 1: залишок M = 10 → deficits [] (покрито, дефіциту немає)
Правка 2: додати надходження {M, Jan15, 10} з датою споживання Jan10 →
  coverable [M] (earliestCoverDate Jan15)
Перерахунок миттєвий, розклад операцій не перебудовується.
```

### Сценарій D — Дата споживання з операцій
```
Операції вузла P стартують Jan10; BOM: P → M (material)
Очікування: demandDatesByMaterial → { M: Jan10 }
```
