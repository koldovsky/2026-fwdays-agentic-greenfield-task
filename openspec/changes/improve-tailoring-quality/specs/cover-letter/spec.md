# cover-letter (delta)

## MODIFIED Requirements

### Requirement: Grounded cover-letter generation
The system SHALL generate the cover letter for paid users via the dedicated
grounded LLM prompt (`buildCoverLetterPrompt`, promoted from dead code to the
default paid experience) in a server-side generation step, since the render
route (`POST /api/export/cover-letter`) is paid-gated and rendering SHALL stay
separate from generation. The prompt is grounded only in the candidate's CV
sentences and the confirmed clarifying-question answers; requirements steer
emphasis and the inferred careerStage calibrates tone, never adds claims. The
target quality is a natural, specific, first-person narrative appropriate to
the inferred seniority, not a bullet list reflowed to prose; the approved
example letter is committed as the honesty-eval quality fixture. The
deterministic bullet-reflow builder (`buildCoverLetterDocument`) SHALL remain
as the fail-honest fallback whenever generation or verification fails or the
LLM is unavailable, so a paid export never returns a blank (NFR-OBS-01).
Output is Ukrainian-first via `shared/lib/i18n` with an English fallback. The
cover-letter context SHALL remain on the `GROUNDING_FORBIDDEN` denylist: the
letter never feeds the bullet grounding pass. Implements FR-COVERLETTER-01,
FR-COVERLETTER-02, BC-HONESTY-01, BC-HONESTY-02, NFR-I18N-01, NFR-OBS-01,
NFR-PERF-02.

#### Scenario: Paid user gets the LLM letter by default
- **WHEN** a paid user reaches the Export step and requests a cover letter with the LLM available
- **THEN** the letter is generated by the grounded prompt and reads as first-person narrative prose, not a sequence of the kept bullets verbatim

#### Scenario: Generation failure falls back to the deterministic letter
- **WHEN** the letter generation call fails, times out, or returns unparseable output
- **THEN** the deterministic reflow letter is produced instead, with a calm coded surface and never a blank or a raw error (NFR-OBS-01)

#### Scenario: Excluded bullets do not leak into the letter
- **WHEN** an `overclaim-risk` bullet was excluded from the resume export by default
- **THEN** its unsupported claim appears in neither the LLM letter nor the fallback letter (BC-HONESTY-02)

#### Scenario: Letter never feeds bullet grounding
- **WHEN** a tailoring runs with letter generation enabled
- **THEN** the recorded grounding-pass context contains no cover-letter context key; the trajectory eval fails any trace where one appears (BC-HONESTY-01)

#### Scenario: Ukrainian-first output
- **WHEN** the cover letter is produced on either path
- **THEN** its framing copy is Ukrainian-first with an English fallback, sourced through `shared/lib/i18n`, no hardcoded UI strings

## ADDED Requirements

### Requirement: Cover-letter claim verification
The system SHALL verify every LLM-generated cover letter before it is shown or
exported: each factual claim in the letter is checked against the candidate's
CV sentences and the confirmed clarifying-question answers, in a verification
step that shares no context with the generation call, mirroring the two-pass
bullet honesty model. A letter with any unverifiable claim SHALL NOT ship: the
system falls back to the deterministic reflow letter. Unverified LLM prose is
never exported, and verification cannot be disabled. The existing two-pass
bullet grounding (FR-BULLETS-03) is a separate lane and is not modified by
this step. Honesty-eval fixtures SHALL cover both a grounded letter that passes
and an overclaiming letter that is rejected. Implements FR-COVERLETTER-01,
BC-HONESTY-01, BC-HONESTY-02, FR-BULLETS-03, NFR-OBS-01.

#### Scenario: Verified letter ships
- **WHEN** the generated letter's claims all trace to a CV sentence or a confirmed answer
- **THEN** the letter passes verification and becomes the exportable cover letter

#### Scenario: Overclaiming letter is rejected, fallback ships
- **WHEN** the generated letter contains a skill, number, or experience absent from the CV and the confirmed answers
- **THEN** verification rejects it, the deterministic fallback letter ships instead, and the unverified prose is never exported

#### Scenario: Verification failure fails honest
- **WHEN** the verification call itself fails or returns unparseable output
- **THEN** the LLM letter is treated as unverified and the deterministic fallback ships (never ship unverified prose)

#### Scenario: Bullet grounding lane is untouched
- **WHEN** letter generation and verification run for a tailoring
- **THEN** the bullet generation and grounding passes execute exactly as without a letter, with unchanged inputs and unchanged overclaim flags (FR-BULLETS-03)
