# Proposal: order-dashboard

## Що і чому

Зведена таблиця по замовленнях — швидкий огляд стану всіх замовлень: коли
готові, наскільки запізнюються, що заблоковано. Головний екран для планувальника
після побудови розкладу (ціль оптимізації №1 — вчасність).

## Проблема яку вирішуємо

Результат планування містить дати готовності й запізнення по кожному замовленню,
але без зведеної таблиці планувальник не бачить загальної картини і не може
швидко знайти проблемні замовлення.

## Що змінюється

Екран зведення по замовленнях:
1. Таблиця: номер, виріб, кількість, дата здачі, розрахована дата готовності,
   відхилення (робочих днів), статус (FR-ORD-01)
2. Статуси: «В графіку», «Під загрозою» (≤ 2 робочі дні), «Запізнення»,
   «Заблоковано матеріалом» (FR-ORD-02)
3. Клік по рядку → розгортається дерево BOM із плановими датами і статусом
   кожного вузла (FR-ORD-03)
4. Сортування за замовчуванням: найбільше запізнення зверху (FR-ORD-04)
5. Підсумковий рядок: усього / в графіку / під загрозою / із запізненням (FR-ORD-05)

## Що НЕ входить в цю зміну

- Алгоритм планування — capability `scheduling`
- Гантт і гістограми — окремі capability
- Матеріальне забезпечення (детальна таблиця дефіцитів) — capability `material-check`

## Ключове рішення: похідні дані як чисті функції

Обчислення статусів, сортування, підсумків і побудова дерева BOM із плановими
датами — **чисті функції** у `lib/dashboard/` (тестуються vitest). Компонент
`OrderDashboard` — лише рендер таблиці з розкриттям рядків.

## Критерій готовності

Таблиця показує всі замовлення зі статусами й відхиленням, сортована за
запізненням, із підсумковим рядком і розкриттям дерева BOM; чисті функції покриті
unit-тестами; застосунок збирається.
