# Specs: order-dashboard

Вимоги з PRD v0.3 (capability `order-dashboard`, FR-ORD-01..05). ID для трасування.

- **FR-ORD-01** Таблиця замовлень: номер, виріб, кількість, дата здачі клієнту,
  розрахована дата готовності, відхилення (робочих днів), статус.
- **FR-ORD-02** Статуси: «В графіку», «Під загрозою» (≤ 2 робочі дні),
  «Запізнення», «Заблоковано матеріалом».
- **FR-ORD-03** Клік на рядок → розгортається дерево BOM із плановими датами і
  статусом кожного вузла.
- **FR-ORD-04** Сортування за замовчуванням: найбільше запізнення зверху.
- **FR-ORD-05** Підсумковий рядок: усього замовлень / в графіку / під загрозою /
  із запізненням.

## Сценарії тестування

### Сценарій A — Похідні статуси
```
Замовлення:
  O1 due +10 днів, ready +5 → В графіку (слак великий)
  O2 due +3 днів, ready due-1 → Під загрозою (слак ≤ 2)
  O3 ready > due, delay 4 → Запізнення
  O4 у deficit.blockedOrderIds → Заблоковано матеріалом
Очікування: кожному замовленню присвоєно правильний статус
```

### Сценарій B — Сортування і підсумок
```
Вхід: замовлення з delayDays 0, 4, 2, 0(blocked)
Очікування:
  порядок: delay 4, delay 2, потім 0 (blocked вище on-schedule за важливістю)
  summary: total=4, late=1(+O з delay2=2 late), atRisk, onSchedule, blocked=1
```

### Сценарій C — Дерево BOM із датами і статусами
```
Операції замовлення O1: вузли O1#A (корінь), O1#A/B, O1#A/B/D
Очікування:
  buildBomTree повертає корінь O1#A з дитиною O1#A/B, у якої дитина O1#A/B/D
  для кожного вузла plannedStart=min(start), plannedEnd=max(end)
  статус вузла = найгірший статус його операцій
```
