# Specification: Dashboard and Analytics (`dashboard-analytics`)

## Glossary and Definitions

| Термін | Визначення |
| :--- | :--- |
| **Dashboard** | Веб-інтерфейс особистого кабінету користувача, доступний за маршрутом `/dashboard`. |
| **Precision Hub** | Дизайн-система інтерфейсу, що базується на стилі Pure Light Mode з високим рівнем контрасту, мінімалістичними тінями, монохромними рамками та чіткою типографікою. |
| **Recharts** | Бібліотека для побудови реактивних інтерактивних графіків у React. |
| **Apps Script Code** | Готовий скрипт для Google Таблиць, який містить API-ключ користувача та URL-адресу платформи для автоматичного відправлення конверсій до `ingestion-api`. |
| **CRM / Telephony Credentials** | Чутливі дані доступу (хост, логін, пароль, API-токени), які використовуються для майбутніх інтеграцій. |

## Scope & Non-Goals

### Bounded Scope
- Створення сторінки особистого кабінету користувача за адресою `/dashboard`.
- Форма для збереження інтеграційних доступів до CRM та телефонії з обов'язковим шифруванням паролів та API-ключів за алгоритмом AES-256-GCM.
- Генератор інтеграційного скрипта Google Apps Script та генерація/перегляд API-ключа.
- Інтерактивні інструкції для GA4, Google Ads, Google Cloud та Binotel.
- Панель аналітики з вибором періоду (до 14 місяців) та сумарними картками метрик.
- Лінійний графік динаміки конверсій та два кругових графіки розподілу за джерелами та каналами.
- Таблиця останніх 100 конверсій з пагінацією та фільтрами за джерелом та каналом.
- Забезпечення продуктивності рендерингу та побудови звітів з локальної БД ≤ 500 мс.

### Non-Goals
- Реалізація фонових процесів, які самі підключаються до CRM чи телефонії для імпорту (кабінет лише зберігає ці доступи для майбутнього використання).
- Експорт звітів у PDF чи Excel (поза межами MVP).
- Зберігання даних конверсій за період, більший ніж 14 місяців.

## ADDED Requirements

### Requirement: CRM and Telephony Access Form (FR-DASH-01)
Система SHALL надавати форму в особистому кабінеті для внесення та збереження доступів користувача до CRM (URL, логін, пароль) та Телефонії (URL, логін, пароль, REST API ключі). Чутливі поля (паролі, API-ключі) MUST бути зашифровані за допомогою AES-256-GCM перед збереженням у базі даних.

#### Scenario: Успішне збереження та шифрування доступів
- **GIVEN** користувач є автентифікованим та має активну сесію особистого кабінету
- **WHEN** користувач заповнює поля доступу CRM та телефонії на сторінці кабінету та натискає "Зберегти"
- **THEN** система валідує URL-адреси (вони мають бути коректними посиланнями)
- **AND** система шифрує пароль CRM та API-ключ телефонії за допомогою алгоритму AES-256-GCM (з використанням `ENCRYPTION_KEY` з конфігурації)
- **AND** система оновлює запис користувача в таблиці `users` в БД
- **AND** повертає повідомлення про успішне збереження без виведення шифрованих значень у відповіді API

#### Scenario: Відображення збережених налаштувань
- **GIVEN** користувач є автентифікованим та має активну сесію особистого кабінету
- **WHEN** користувач завантажує сторінку налаштувань інтеграцій
- **THEN** система зчитує дані з таблиці `users`
- **AND** перевіряє наявність збережених паролів та API-ключів без їх дешифрування на сервері (якщо відповідне поле в базі даних не порожнє та не дорівнює NULL, то дані наявні)
- **AND** відображає текстові поля (логіни, URL) як є, а паролі/ключі маскує (наприклад, відображає плейсхолдер у вигляді крапок або пусте поле з позначкою "збережено")

### Requirement: Instructions Accordion (FR-DASH-02)
Система SHALL відображати детальні інтерактивні інструкції з налаштування GA4, Google Ads, Google Cloud (включаючи вимоги до надання прав Editor, Project IAM Admin, BigQuery Admin для сервісного акаунту `auto@acontrol.pro`) та Binotel.

#### Scenario: Перегляд інструкцій користувачем
- **GIVEN** користувач є автентифікованим та має активну сесію особистого кабінету
- **WHEN** користувач переходить до розділу інструкцій у кабінеті
- **THEN** система рендерить структурований віджет (наприклад, Accordion) з окремими кроками для кожної платформи
- **AND** інструкція для Google Cloud чітко вказує email сервісного акаунту `auto@acontrol.pro` та необхідні ролі (Editor, Project IAM Admin, BigQuery Admin)

### Requirement: API Key and Apps Script Generator (FR-DASH-03)
Система SHALL дозволяти користувачеві генерувати та копіювати унікальний API-ключ, а також автоматично формувати готовий код Google Apps Script, підставляючи в нього цей API-ключ та поточний домен платформи.

#### Scenario: Генерація нового API-ключа
- **GIVEN** користувач є автентифікованим та має активну сесію особистого кабінету
- **WHEN** користувач натискає кнопку "Згенерувати новий API-ключ" та підтверджує дію
- **THEN** система створює новий випадковий рядок (API-ключ довжиною ≥ 32 символи)
- **AND** обчислює його SHA-256 хеш
- **AND** зберігає цей хеш у полі `api_key_hash` таблиці `users`
- **AND** показує відкритий API-ключ користувачеві ОДИН РАЗ із кнопкою швидкого копіювання
- **AND** оновлює згенерований Apps Script код, де параметр `API_KEY` замінюється на новий ключ

#### Scenario: Копіювання коду Apps Script
- **GIVEN** користувач є автентифікованим та має активну сесію особистого кабінету
- **WHEN** користувач відкриває вкладку Apps Script у кабінеті
- **THEN** система відображає блок коду (textarea або code block) з кнопкою "Копіювати"
- **AND** блок коду містить коректні параметри: поточний домен (наприклад, `https://acontrol.pro/api/conversions`) та API-ключ користувача (якщо він уже був згенерований, інакше виводиться інструкція згенерувати ключ спочатку)

### Requirement: Analytics Period Filter (FR-DASH-04)
Система SHALL дозволяти користувачеві обирати період аналітики (за замовчуванням останні 30 днів) з обмеженням максимум у 14 місяців для побудови всіх аналітичних звітів на дашборді.

#### Scenario: Зміна періоду аналітики
- **GIVEN** користувач є автентифікованим та має активну сесію особистого кабінету
- **WHEN** користувач обирає новий період (наприклад, останні 90 днів або custom діапазон) через селектор дат
- **THEN** система перевіряє, що початкова дата не перевищує 14 місяців від поточної дати
- **AND** система перевіряє, що кінцева дата не є ранішою за початкову дату (`endDate >= startDate`), та що обидві дати є коректними ISO-8601/timestamp значеннями
- **AND** система перевантажує дані для карток метрик, графіків та таблиці на основі вибраного діапазону дат

### Requirement: Summary Metric Cards (FR-DASH-05)
Система SHALL обчислювати та відображати 4 ключові метрики за вибраний період: загальна кількість отриманих конверсій, сумарна цінність конверсій (у валюті UAH), кількість рекламних конверсій (`is_ad_conversion = true`) та їхній відсотковий відносний показник від загальної кількості.

#### Scenario: Розрахунок показників метрик
- **GIVEN** користувач є автентифікованим та має активну сесію особистого кабінету
- **WHEN** завантажується аналітика для обраного періоду
- **THEN** система виконує агрегаційні запити до таблиці `conversions` для поточного користувача
- **AND** розраховує:
  - `Total Conversions` (COUNT усіх записів)
  - `Total Value` (SUM поля `conversion_value`)
  - `Ad Conversions` (COUNT записів, де `is_ad_conversion = true`)
  - `Ad Conversions %` (відношення `Ad Conversions` до `Total Conversions` помножене на 100, округлене до одного десяткового знаку)
- **AND** якщо конверсій немає, відображає нульові значення (`0`, `0 ₴`, `0`, `0%`)

### Requirement: Conversion Trend Line Chart (FR-DASH-06)
Система SHALL відображати лінійний графік (Line Chart) динаміки передачі конверсій за обраний період (із динамічним групуванням за днями/тижнями/місяцями), використовуючи бібліотеку Recharts.

#### Scenario: Рендеринг лінійного графіка динаміки
- **GIVEN** користувач є автентифікованим та має активну сесію особистого кабінету
- **WHEN** завантажується аналітика з наявними конверсіями
- **THEN** система групує записи конверсій за датою: за днями для періодів до 90 днів включно, та за тижнями/місяцями для довших періодів (до 14 місяців)
- **AND** будує графік з двома лініями: "Загальні конверсії" та "Рекламні конверсії"
- **AND** при наведенні на точку графіка відображає спливаючу підказку (Tooltip) з точними даними на цей інтервал

### Requirement: Distribution Pie Charts (FR-DASH-07)
Система SHALL відображати дві кругові діаграми (Pie Charts) розподілу конверсій за обраний період:
1. За рекламними джерелами (`ad_source` - Google Ads, Meta Ads, Organic, інше).
2. За каналами (`channel` - Вебсайт, Телефонія, Месенджери, інше).

#### Scenario: Рендеринг діаграм розподілу
- **GIVEN** користувач є автентифікованим та має активну сесію особистого кабінету
- **WHEN** завантажується аналітика з наявними конверсіями
- **THEN** система групує конверсії за `ad_source` та `channel` відповідно
- **AND** будує дві кругові діаграми з легендами та різними кольорами для секторів
- **AND** сектори відображають відсоткову частку кожного джерела/каналу

### Requirement: Conversions Log Table (FR-DASH-08)
Система SHALL відображати таблицю останніх 100 конверсій користувача за обраний період із можливістю пагінації (по 10 записів на сторінку) та швидкої фільтрації за рекламним джерелом (`ad_source`) та каналом (`channel`). З метою оптимізації продуктивності, фільтрація та пагінація виконуються на клієнтській стороні виключно в межах завантажених останніх 100 конверсій за обраний період.

#### Scenario: Фільтрація та пагінація таблиці конверсій
- **GIVEN** користувач є автентифікованим та має активну сесію особистого кабінету
- **WHEN** користувач застосовує фільтр за джерелом (наприклад, `Google Ads`)
- **THEN** таблиця оновлюється, відображаючи лише відповідні конверсії серед завантаженого пакету останніх 100 записів
- **AND** пагінація автоматично перераховує кількість сторінок на основі цього відфільтрованого списку

### Requirement: Dashboard Load Performance (NFR-PERF-02)
Час повного завантаження сторінки особистого кабінету та рендерингу графіків з локальної бази даних SHALL становити ≤ 500 мс для 95% запитів (p95).

#### Scenario: Швидке завантаження звітів
- **GIVEN** користувач є автентифікованим та має активну сесію особистого кабінету
- **WHEN** користувач завантажує сторінку `/dashboard`
- **THEN** система використовує оптимізовані індекси в таблиці `conversions` (`idx_conversions_user_id_conversion_time`) для швидкого фетчингу та агрегації даних
- **AND** під час очікування відповіді від API кабінет відображає Skeleton loaders для віджетів та графіків, щоб уникнути різких стрибків інтерфейсу
