## 2. Back-end — session manager

- [x] 2.1 Create `back-end/src/tv/session.ts` — per-TV actor: owns pool + queue + state + event emitter. `connect()`, `disconnect()`, `enqueue(fn)`. Session emits `state` on every transition; queue is a `p-queue` with concurrency 1 so state-changing commands never race.
- [x] 2.2 Create `back-end/src/tv/manager.ts` — `Map<UDN, Session>`; subscribes to registry events from `upnp-tv-discovery` to enforce the `offline → Offline` and `online → Disconnected` transitions. Also primes its internal `deviceIndex` from `registry.snapshot()` so sessions started after discovery has already run still find their `{ ip, port }`.
- [x] 2.3 Implement reconnect: 200/500/1000/2000/5000 ms backoff, cap 5; on cap, transition to `Disconnected`. Delays configurable via `SessionOptions.reconnectDelaysMs` so tests can drive the state machine in milliseconds.
- [x] 2.4 Implement pairing: on `connect()` with no token in the store, call `getAccessToken` per the samsung-ip-control-protocol skill; log a one-line prompt directing the user to confirm on the TV; persist the token on success. **Design gap noted**: the Samsung IP Control PDF provisions AccessToken out-of-band and does not document a `getAccessToken` JSON-RPC method. Implemented per the design's speculative MVP flow, but on a stock TV the call returns `-32601` → `TvNotSupported`; the log line + `MYTV_TOKEN_<UDN>` env override tell the user how to preload the token instead. Test-side stub returns a fake token so the state machine still exercises the "persist on pair" path.
- [x] 2.5 Wire heartbeat: while `Connected`, issue a lightweight read-only method (e.g. `getSystemInfo`) every 15 s; on error, transition to `Reconnecting`. Interval configurable so tests don't have to wait 15 s.

- [x] 5.1 Create `front-end/src/data/useDeviceSession.ts` — subscribes to the `devices` `session` events for a given UDN, plus one-off `GET /api/devices/:udn/session` on mount; returns `{ state, connect(), disconnect() }`. `createWebSocket`, `fetchInitial`, `postConnect`, `postDisconnect` are all injectable for tests.
- [x] 5.2 Wire `RemoteScreen` header to the hook — the `Badge` reflects the session state (via a small `sessionToBadgeStatus` mapper: `Connected`→`online`, `Connecting`→`connecting`, others→`offline`); the back button calls `disconnect()` before navigating. All command controls (D-pad, transport, volume, power, app shortcuts) get `disabled={state !== 'Connected'}` — `IconButton` has a native `disabled` prop; DS controls without one (`DPad`, `Slider`, `AppShortcut`) are wrapped in a container with `pointer-events: none` + reduced opacity + `aria-disabled` so they read as non-interactive without extending the DS in this change.
