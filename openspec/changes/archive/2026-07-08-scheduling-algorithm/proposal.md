# Proposal: scheduling-algorithm

## Що і чому

Серцевина APS-планувальника — чиста функція `schedule()` що перетворює
вхідні виробничі дані на оптимальний розклад операцій.

Без цього модуля неможливо реалізувати жодну UI-capability (Гантт,
завантаженість, дашборд замовлень). Всі інші модулі залежать від нього.

## Проблема яку вирішуємо

Планувальник вручну будує розклад в Excel: розставляє операції по РЦ,
відстежує залежності між підзбірками, перераховує при змінах. При 1000
замовленнях це займає день роботи і все одно містить помилки.

## Що змінюється

Замість ручної роботи — детермінований алгоритм що:
1. Розгортає дерево BOM для всіх замовлень
2. Розраховує нетто-потребу в матеріалах (MRP)
3. Розставляє операції backward від дати замовлення
4. Розподіляє операції між РЦ всередині ГРЦ за мінімальним завантаженням
5. Вирішує конфлікти на РЦ за Critical Ratio
6. Повертає 2 варіанти розкладу + метрики

## Що НЕ входить в цю зміну

- UI (Гантт, гістограми) — окремі capability
- Імпорт/парсинг файлів Excel — окремий модуль
- Збереження стану в IndexedDB — окремий модуль
- Ручне закріплення операцій — наступна ітерація

## Критерій готовності

`lib/scheduler/` покрита unit-тестами на 100%; функція `schedule()`
приймає plain JS об'єкти і повертає plain JS об'єкти без будь-яких
залежностей від React, DOM або Next.js.
