## Context

Slice 001 is the first capability in Cadence and the authentication boundary for everything
downstream. It was implemented against [`docs/specs/001-auth-email.md`](../../../docs/specs/001-auth-email.md)
(ratified) and [`docs/architecture.md`](../../../docs/architecture.md) (§2.1 data model, §8 auth)
before OpenSpec was adopted; this document records the decisions as built. Requirement text is
authoritative in [`docs/requirements.md`](../../../docs/requirements.md) (FR-AUTH-*, NFR-SEC-*).

## Goals / Non-Goals

**Goals:**
- Email + password accounts with server-side session cookies.
- A `CurrentUser` dependency and a user_id-scoped repository pattern that every later data slice reuses.
- Password hashing, protective cookie attributes, and CSRF protection.

**Non-Goals:**
- OAuth sign-in (Google/GitHub) and the `oauth_identities` table — slice 009 (FR-AUTH-04/05).
- Password reset and email verification — decision A-5.
- Anything downstream of auth (timer, sessions, categories, metrics, coach, extension).

## Decisions

- **Server-authoritative sessions.** A `user_sessions` row holds an opaque 256-bit token (UNIQUE,
  indexed), distinct from the `BIGINT` primary key; the cookie carries the token, not the id.
  30-day sliding expiry, extended on authenticated activity. (architecture §8.2)
- **Password hashing:** bcrypt via `passlib[bcrypt]`, cost factor 12, per-hash random salt. Plaintext
  is never stored or logged. (NFR-SEC-01)
- **Cookie + CSRF:** `HttpOnly; SameSite=None; Path=/`, with an env-driven `Secure` flag (off for
  local http, on in prod). `SameSite=None` reopens CSRF, so a double-submit CSRF token is issued at
  login and required on all mutating requests. (NFR-SEC-02, architecture §8.2 / gap G-3)
- **Per-user isolation:** every repository method takes `user_id` from the auth dependency and scopes
  every query by it; the only exceptions are the auth-bootstrap methods that establish identity.
  (FR-AUTH-07, NFR-SEC-03)
- **Migration:** one Alembic migration `0001_auth_email` creates `users` and `user_sessions` and
  enables the `citext` extension; `email` is `CITEXT UNIQUE`. Autogenerated SQL was hand-reviewed.

## Risks / Trade-offs

- `SameSite=None` is required so the browser extension can share the session across origins but
  weakens CSRF defenses; mitigated by the mandatory double-submit CSRF token.
- `password_hash` is nullable to accommodate future OAuth-only accounts (slice 009); email/password
  registration always sets it, so the null case cannot occur for this slice.
- Recorded retroactively, so the standing risk is spec/implementation drift. Mitigated by the
  `@trace`-based Python traceability harness and by keeping `docs/specs/001-auth-email.md` as that
  harness's anchor while OpenSpec holds the detailed contract.
