## Why

Реалізація можливості реєстрації та авторизації через Telegram (`telegram-auth`) є ключовим етапом побудови платформи, який виступає "вхідними дверима" системи. Відповідно до вимог проекту, безпечний доступ до кабінету користувача та збереження його даних неможливі без обов'язкового зв'язку профілю з Telegram-ботом. Це забезпечує безпарольний вхід та миттєвий зв'язок для майбутніх сповіщень.

## What Changes

Впровадження цієї можливості включає такі зміни:
- Створення та конфігурація Telegram-бота для збору email та адреси сайту (`website_url`) під час команди `/start`.
- Інтеграція Telegram Route Handler у Next.js для обробки вебхуків Telegram API або використання `node-telegram-bot-api`.
- Реалізація сторінок реєстрації (`/register`) та входу (`/login`) з генерацією QR-коду та посилання типу `t.me/bot?start=reg_<temp_token>`.
- Реалізація механізму безпарольного входу (Magic Link або 6-значний одноразовий код), що надсилається в Telegram-бот.
- Налаштування механізму автоматичного перенаправлення (redirect) користувача в особистий кабінет після підтвердження в боті (наприклад, через Server-Sent Events, WebSockets або періодичний polling).
- Локалізація бота та інтерфейсу виключно українською мовою з практичним, спокійним тоном без знаків оклику.

## Capabilities

### New Capabilities
- `telegram-auth`: Реєстрація та авторизація користувача через Telegram-бот, генерація QR-кодів/посилань реєстрації, автоматичний редірект та безпарольний вхід за допомогою Magic Link або 6-значних одноразових кодів.

## Impact

- **Нові залежності**: додавання `node-telegram-bot-api` (якщо використовується ця бібліотека) або схожих інструментів, бібліотеки для генерації QR-кодів (наприклад, `qrcode`).
- **База даних**: активне використання створених раніше таблиць `users`, `sessions`, `magic_links` у `db/schema/` для збереження профілів, сесій та тимчасових токенів.
- **Маршрути Next.js**: створення сторінок `/register`, `/login`, а також Route Handlers для вебхуків `/api/telegram/webhook`, авторизації `/api/auth/magic` та перевірки статусу сесії `/api/auth/session`.
- **Конфігурація**: додавання змінних `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `NEXT_PUBLIC_APP_URL` у `.env`.
