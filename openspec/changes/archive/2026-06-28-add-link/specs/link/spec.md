# link Specification

## Purpose

Each assessment cycle exposes a single private respondent URL `/respond/[token]` that
HR shares manually. The token is the only credential a respondent needs, resolves to
exactly one cycle, carries no personal data, and is not guessable or enumerable. HR
copies the link with a one-click action on the cycle detail page; the token resolves
to the cycle's current persisted `status`, so a `collecting` cycle loads a respondent
landing, while a `done`, `expired`, or unknown token shows a calm explanatory page
rather than a stack trace or a generic error. This capability owns the respondent-link
contract (FR-LINK-01..03, BC-PRIVACY-02, NFR-SEC-01).

## ADDED Requirements

### Requirement: Private respondent URL with one-click copy (FR-LINK-01)

The system SHALL expose, for every cycle, a private respondent URL of the form
`/respond/[token]`, where `[token]` is the cycle's unique opaque token. The cycle
detail page in the HR cabinet SHALL provide a "Copy link" client-side action that
writes the full URL to the clipboard and shows an inline transient confirmation. The
action SHALL confirm success inline ("Посилання скопійовано") and SHALL NOT display
the cycle's internal database id, the subject's personal data, or any other cycle's
link. The URL SHALL contain only the token (BC-PRIVACY-02).

#### Scenario: HR copies a cycle's respondent link from the cycle detail page

- **GIVEN** an authenticated HR manager viewing the detail page for a cycle
- **WHEN** they activate the "Copy link" action
- **THEN** the full respondent URL `/respond/<token>` for exactly that cycle is
  written to the clipboard, an inline "Посилання скопійовано" confirmation appears
  transiently (approximately 2 seconds), with no page navigation and no exposure of
  the cycle database id or the subject's personal data

#### Scenario: Copied link opens the correct respondent landing for a collecting cycle

- **GIVEN** HR has copied the respondent URL for a cycle whose persisted `status` is
  `collecting`
- **WHEN** the copied URL `/respond/<token>` is opened in a browser (no sign-in
  required)
- **THEN** the respondent landing page for that one cycle loads, showing the subject's
  first name, methodology, deadline with days remaining, and the snapshot questions in
  order — with no cycle id visible in the URL or in the rendered HTML

#### Scenario: Clipboard API failure is surfaced inline without a crash

- **GIVEN** an HR manager on a page where `navigator.clipboard.writeText` rejects
  (e.g. non-HTTPS or permission denied)
- **WHEN** they activate the "Copy link" action
- **THEN** an inline "Не вдалося скопіювати" message is shown in Ukrainian; no
  unhandled exception is thrown; no stack trace is rendered

### Requirement: Token resolves to exactly one cycle, non-enumerable, no personal data in URL (FR-LINK-02)

The system SHALL use the existing `generateCycleToken` function from
`lib/cycles/link-token.ts` as the sole token generator. No second generator SHALL
exist. The token is 32 cryptographically random bytes encoded as unpadded base64url
(43-character `[A-Za-z0-9_-]` string), unique across all cycles (`Cycle.token
@unique`), non-sequential, and not derived from any cycle attribute or subject
identity. The token-bearing URL SHALL contain no personal data and no internal
database id; the token-to-cycle mapping lives only in the database
(FR-LINK-02, TC-ARCH-01, BC-PRIVACY-02, BC-PRIVACY-04).

#### Scenario: Each token maps to exactly one cycle

- **GIVEN** a valid token for a cycle
- **WHEN** the respondent route resolves the token via `db.cycle.findUnique`
- **THEN** it loads exactly the one cycle whose `token` equals the supplied value;
  no other cycle's data is reachable through that token

#### Scenario: The URL carries no personal data or internal id

- **GIVEN** a respondent URL `/respond/<token>` and the rendered respondent landing page
- **WHEN** the URL and page HTML are examined
- **THEN** neither contains the subject's surname, email, phone, Telegram handle,
  or the cycle's internal database id; the token-to-cycle mapping exists only in the
  database; the subject's first name may appear in the greeting but no other PII is
  present

#### Scenario: A single canonical token generator is used throughout the codebase

- **GIVEN** the full codebase
- **WHEN** all token-generation call sites are listed
- **THEN** every cycle token is generated by `generateCycleToken` from
  `lib/cycles/link-token.ts` and no other function generates cycle tokens

### Requirement: Boundary validation rejects malformed tokens before any DB call (FR-LINK-03, TC-VALID-01)

The respondent route SHALL validate the inbound token with `tokenBoundarySchema`
(`z.string().regex(/^[A-Za-z0-9_-]{43}$/)`) before any database lookup. Any token
that is empty, shorter or longer than 43 characters, contains an out-of-charset
character, or is oversized SHALL be rejected at the boundary, and the same calm
not-found page SHALL be shown — never a 500, a stack trace, or a raw exception
(FR-LINK-03, TC-VALID-01, NFR-OBS-01).

#### Scenario: Malformed token is rejected before any database call

- **GIVEN** a token value in the URL that fails the boundary schema — empty, 42
  characters, 44 characters, a 10 000-character string, or a character outside
  `[A-Za-z0-9_-]`
- **WHEN** the respondent route receives it
- **THEN** `tokenBoundarySchema.safeParse` rejects the value without a DB call, and
  the same calm not-found page is shown as for an unknown token, with no 500, no
  stack trace, and no oracle distinguishing malformed from unknown

### Requirement: Calm explanatory page for closed, expired, or unknown tokens (FR-LINK-03)

The system SHALL render a calm, plain-language explanatory page when a respondent
opens a token that does not resolve to a collecting session. The landing decision
SHALL be made strictly from the persisted `status` enum value read from the DB row,
not by re-deriving the deadline at request time. Unknown and malformed tokens SHALL
render the same not-found message (no enumeration oracle). Done cycles SHALL always
show the completed explanation even if their deadline is in the past. No stack trace,
generic framework error, subject personal data, or hint of other cycles SHALL appear
(FR-LINK-03, FR-CYCLE-04, BC-PRIVACY-02, NFR-OBS-01).

#### Scenario: Unknown token shows a calm not-found explanation

- **GIVEN** a well-formed 43-character `[A-Za-z0-9_-]` token that matches no cycle
  in the database
- **WHEN** a respondent opens `/respond/<unknown-token>`
- **THEN** "Посилання не знайдено або застаріло" is shown (or equivalent English in
  the en locale); no stack trace, no generic error screen, no disclosure of whether
  any other cycle exists, and no cycle id or subject data in the page

#### Scenario: Expired cycle shows the "window closed" explanation

- **GIVEN** a token whose cycle has persisted `status` equal to `expired`
- **WHEN** a respondent opens that link
- **THEN** "Час на відповідь сплив" is shown; no answer form or question list is
  rendered; no stack trace; the page does not show the "completed" wording

#### Scenario: Done cycle shows the "completed" explanation regardless of deadline

- **GIVEN** a token whose cycle has persisted `status` equal to `done`, and whose
  `deadline` is in the past
- **WHEN** a respondent opens that link
- **THEN** "Відповідь вже надано" is shown; no answer form is rendered; no "expired"
  wording; the landing is determined by the persisted `done` status, not the deadline

#### Scenario: Done cycle whose deadline is in the future still shows "completed"

- **GIVEN** a token whose cycle has persisted `status` equal to `done`, and whose
  `deadline` is still in the future
- **WHEN** a respondent opens that link
- **THEN** "Відповідь вже надано" is shown; the future deadline does not cause the
  page to render as `collecting`; status is read from the persisted enum value

### Requirement: Respondent landing shows cycle context with privacy invariants (FR-LINK-01, FR-LINK-03, BC-PRIVACY-02)

When the token resolves to a `collecting` cycle, the respondent page SHALL show the
subject's FIRST NAME ONLY (first whitespace-delimited word of `fullName`), the
methodology from the template snapshot, the deadline with days remaining, and the
snapshot questions in order (read-only, no answer input controls). No full name, no
email, no phone, no Telegram handle, no cycle database id SHALL appear anywhere in
the rendered HTML.

#### Scenario: Collecting cycle landing shows correct context

- **GIVEN** a token whose cycle has persisted `status` equal to `collecting`, a
  subject with `fullName = "Олена Мельник"`, and a snapshot with methodology
  "Performance Review" and 5 questions
- **WHEN** a respondent opens the link
- **THEN** the page shows "Олена" (not "Олена Мельник"), "Performance Review", the
  deadline in days remaining format, and 5 questions in snapshot order; no answer
  inputs are rendered; no cycle id appears in the HTML

#### Scenario: Subject with a single-word name uses the full single word as greeting

- **GIVEN** a token whose collecting cycle has a subject with `fullName = "Oksana"`
  (no space)
- **WHEN** a respondent opens the link
- **THEN** the greeting shows "Oksana" — the first (and only) word of the name

## Exclusions

- Automated email or messenger delivery of the respondent link is intentionally
  unsupported in the MVP; the link is delivered by manual copy-to-clipboard only.
- Token rotation, manual revocation, or regeneration of a cycle's link is out of
  scope for the MVP.
- Answer capture and submission (respond/form slices).
- Mode selection between form and AI interview (respond slice).
- Copy-link on the cycles list page (only on the cycle detail page in this slice).
- HTTP 404 is intentionally not used for unknown tokens — the server renders a calm
  200 page to avoid enumeration via response code.
