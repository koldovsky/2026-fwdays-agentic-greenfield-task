# Proposal — add-link

## Why this slice exists

A cycle carries a private respondent URL at `/respond/[token]`. Without this slice the
token stored in the `Cycle` table is never exposed as a routable page: the respondent
has nowhere to land, and HR cannot hand off the link. This slice makes the minted token
resolvable to a public respondent landing page and gives HR a one-click "Copy link"
action on the cycle detail page.

## What changes

### FR-LINK-01 — Private respondent URL + copy action

Every cycle exposes `/respond/[token]`. The cycle detail page in the cabinet gains a
"Copy link" client component that writes the full URL to the clipboard and shows an
inline transient confirmation. The URL never contains the cycle database id, the
subject's name, or any other personal data.

### FR-LINK-02 — Token resolves to exactly one cycle, no PII in URL, not enumerable

The token is already generated by `lib/cycles/link-token.ts` (`generateCycleToken`).
This slice REUSES that function — it does NOT introduce a second token generator.
`Cycle.token` carries a `@unique` constraint in the Prisma schema; no schema migration
is needed. The token is 32 cryptographically random bytes encoded as base64url
(43-character `[A-Za-z0-9_-]` string, non-sequential, not derived from any cycle or
subject attribute).

### FR-LINK-03 — Calm explanatory page for closed, expired, or unknown tokens

`app/respond/[token]/page.tsx` currently renders a placeholder `<EmptyState />`. This
slice replaces it with a real server component that:

1. Validates the inbound token with Zod at the boundary (exactly 43 chars,
   `^[A-Za-z0-9_-]{43}$`) before touching the database.
2. Looks up the cycle via `db.cycle.findUnique({ where: { token } })`.
3. If the token is malformed, unknown, or the cycle is in a non-collecting status
   (`done` / `expired`), renders a calm Ukrainian explanatory message. Unknown and
   malformed tokens render the same "not found" message (no enumeration oracle).
4. If the cycle is `collecting`, renders: subject first name (first word of
   `subject.fullName` only — never full name), methodology, snapshot questions in
   order (read-only, no answer inputs — that is the `respond`/`form` slices), and
   the deadline with days remaining.

The landing decision is based on the persisted `status` enum, not re-derived from the
deadline at request time, consistent with FR-CYCLE-04.

## Existing respondent shell

`app/respond/[token]/layout.tsx` already exists (added in the `add-cabinet-shell`
slice). It provides the sidebar-free mobile-first centered column (max 640px). This
slice does NOT modify it.

`app/respond/[token]/page.tsx` exists as a placeholder (`EmptyState` only). This
slice replaces the placeholder body; the file path stays the same.

## Impact

- No schema changes. No new npm dependencies.
- Adds `app/respond/[token]/queries.ts` (server-only, no auth — public route).
- Replaces the body of `app/respond/[token]/page.tsx`.
- Adds a "Copy link" client component used from `app/(cabinet)/cycles/[id]/page.tsx`.
- Extends `lib/i18n/uk.ts` and `en.ts` with a `respondent` namespace.

## Out of scope

- Answer capture and submission (respond/form slices).
- Mode choice: form vs AI interview (respond slice).
- Automated email or messenger delivery of the link (out of MVP scope).
- Token rotation or revocation.
- Copy-link action is on the cycle detail page only; the cycles list row is the
  respond slice's concern (it needs the full respondent context).
