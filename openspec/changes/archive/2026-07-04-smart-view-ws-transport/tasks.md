## 1. Back-end — SSDP discovery layer

- [x] 1.1 Extend `SsdpHit` in `back-end/src/discovery/ssdp.ts` with an optional `server?: string` field. Populate it from the `SERVER` header on M-SEARCH responses (`node-ssdp` exposes it via `headers.SERVER`) and from the parsed `SERVER` header in `parseNotify()`. Both writers use `...(server !== undefined && { server })` so `SsdpHit.server` stays absent (not `undefined`) when the TV omits the header.
- [x] 1.2 Add a `shouldFetch(hit: SsdpHit): boolean` predicate in `back-end/src/discovery/index.ts` — returns `true` iff any of `hit.usn`, `hit.st`, `hit.server` contains the case-insensitive substring `samsung`. Also returns `true` when all three are empty (no headers to filter on — falls through to the post-fetch backstop). Gate `void queue.add(() => handleHit(hit))` on it; log dropped hits at `debug` with `{ location, usn, st, server, source }`.
- [x] 1.3 Add an IP-dedup guard in `back-end/src/discovery/registry.ts` `upsert()`: if `input.udn` is not already in the map and any existing device with `status === 'online'` shares `input.ip`, return `undefined` and let the caller log at `debug`. Existing-UDN upserts (IP change on the same UDN) are unaffected — the guard only fires when a *fresh* UDN would land on a busy IP. Interface signature widened from `upsert(...): Device` to `upsert(...): Device | undefined`; the discovery orchestrator now logs the dedup rejection.

## 2. Back-end — TV transport (Smart View WebSocket)

- [x] 2.1 Promote `ws` from `devDependencies` to `dependencies` in `back-end/package.json` (it's already in the transitive graph via `@fastify/websocket`).
- [x] 2.2 Add `SMART_VIEW_PORT = 8001` at the top of `back-end/src/tv/manager.ts`; when calling `createSession`, pass `port = process.env[\`MYTV_CONTROL_PORT_${udn}\`] ? Number(...) : SMART_VIEW_PORT` — do NOT pass `device.port`.
- [x] 2.3 Rewrite `back-end/src/tv/jsonrpc.ts` — keep the exported `createHttpsTransport` name for now to minimise diff churn, but its body opens a plain `ws.WebSocket` to `ws://<ip>:<port>/api/v2/channels/samsung.remote.control?name=<b64(name)>[&token=<token>]`. The `TvTransport` shape (`call(method, params)`, `close()`) is unchanged, but `call()` becomes fire-and-forget: `ws.send(JSON.stringify({ method, params }))` and resolves as soon as the frame is drained.
- [x] 2.4 Add a `connectHandshake()` method on the transport (called by `session.ts` `tryOpen`) that returns a `Promise<{ token?: string }>` resolved on `{event: "ms.channel.connect"}` and rejected on `{event: "ms.channel.unauthorized"}` / `{event: "ms.channel.timeOut"}` / socket close / 30 s timeout. Rejection value is a `TvError` from `mapWsError`.
- [x] 2.5 Add `mapWsError` to `back-end/src/tv/errors.ts` per D6's table (socket close/error → `TvNotReachable`, `unauthorized` → `TvNotSupported`, `timeOut` → `TvNotReachable`, `ms.error` → `TvFailed`, unknown → `TvUnknown`). Keep `mapRpcErrorCode` and mark it `@deprecated` (still exported until the JSON-RPC unit tests are rewritten).
- [x] 2.6 Replace the heartbeat in `back-end/src/tv/session.ts` — instead of `transport.call(heartbeatMethod, {})`, use `ws.ping()` via a transport-level `ping(): Promise<void>` method that resolves on `pong` within 5 s and rejects on timeout. Session's failure handling (transition to `Reconnecting`) is unchanged. (Also made `handshakeTimeoutMs`/`pingTimeoutMs` configurable via `SessionOptions`, forwarded to the transport factory — needed for fast, deterministic tests and useful for ops tuning.)
- [x] 2.7 Replace the pairing path in `back-end/src/tv/session.ts` `tryOpen()`: drop the speculative `getAccessToken` call. New flow — load token (env override → store), open transport with the current token (or none), await `transport.connectHandshake()`. On success with a new token, persist via `tokenStore.saveToken(udn, token)`. On failure, close the transport and throw the mapped `TvError`.
- [x] 2.8 Extend the logger redactor's `SENSITIVE_KEYS` in `back-end/src/logger.ts` to also strip `token` (lower-case) — Smart View's payload uses that key. `AccessToken` stays for the C5 JSON-RPC vestige until fully removed. Also strip `token=...` query fragments from any URL string passed to a log line (e.g. transport's WS URL) — see D1.
