# Specs: bom-engine

Вимоги з PRD v0.3 (capability `bom` + `mrp`). ID зберігаються для трасування.

## BOM (розгортання виробу)

- **FR-BOM-01** Розгортання BOM рекурсивно з множенням кількостей на кожному рівні.
- **FR-BOM-02** _(UI)_ Ієрархічне дерево виробу — поза межами рушія.
- **FR-BOM-03** Виявлення спільних вузлів між замовленнями і консолідація потреб.
- **FR-BOM-04** Підзбірки без взаємних залежностей можуть плануватися паралельно.
- **FR-BOM-05** Батьківський вузол не стартує раніше завершення всіх дочірніх
  (Finish-to-Start по дереву) → топологічне впорядкування листя → корінь.

## MRP (потреба в матеріалах)

- **FR-MRP-01** Брутто-потреба = розгортання BOM × кількість замовлення (матеріали).
- **FR-MRP-02** Нетто-дефіцит = брутто − залишки − підтверджені надходження до дати
  споживання.
- **FR-MRP-03** Таблиця дефіцитів: матеріал, брутто, залишок, надходження,
  нетто-дефіцит, найраніша дата закриття.
- **FR-MRP-04** Матеріал без надходжень, що покривають дефіцит, — критичний
  (`earliestCoverDate === null`).
- **FR-MRP-05** Кожен дефіцитний матеріал повʼязаний зі списком заблокованих
  замовлень.

## Сценарії тестування

Взяті з `openspec/changes/scheduling-algorithm/specs/requirements.md`,
обмежені рівнем BOM/MRP.

### Сценарій 1 — Простий BOM
```
BOM: A → [B, C]; B → [D]; C → [D]   (D спільна деталь у межах виробу)
Замовлення: 1 шт A
Очікування (рівень BOM):
  expandBom множить кількості на кожному рівні
  topologicalSort: D раніше B і C; A останній
  effectiveQty(D) сумарно = qty(B→D) + qty(C→D)
```

### Сценарій 7 — Спільні вузли між замовленнями
```
2 замовлення, обидва містять D: 10 шт від O1, 15 шт від O2
Очікування:
  findSharedNodes → D з totalQty = 25, orderIds = [O1, O2]
```

### Сценарій 3 — Дефіцит матеріалу
```
Матеріал M: залишок 0, надходжень немає; споживається замовленням
Очікування:
  calcGrossRequirements → M з grossNeed > 0
  buildMaterialDeficits → netDeficit > 0, earliestCoverDate = null (критичний),
    blockedOrderIds містить замовлення-споживача
```
