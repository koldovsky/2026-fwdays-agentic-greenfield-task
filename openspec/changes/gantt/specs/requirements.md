# Specs: gantt

Вимоги з PRD v0.3 (capability `gantt`, FR-GANTT-01..09). ID для трасування.

- **FR-GANTT-01** Гантт по РЦ: вісь X — час, вісь Y — РЦ, згруповані по ГРЦ.
- **FR-GANTT-02** Кожна смуга: назва операції, номер замовлення, номенклатура вузла.
- **FR-GANTT-03** Кольори: синій=в нормі, жовтий=ризик (≤2 роб. дні), червоний=
  запізнення, сірий=заблоковано матеріалом, штрихування=закріплено вручну.
- **FR-GANTT-04** Клік по смузі → бокова панель: деталі операції, місце в BOM,
  залежні операції, потрібні матеріали.
- **FR-GANTT-05** Масштаб осі часу: година / день / тиждень / місяць — без
  перезавантаження.
- **FR-GANTT-06** Фільтри: ГРЦ, РЦ, замовлення, номенклатура, статус, лише
  критичний шлях.
- **FR-GANTT-07** Drag-and-drop смуги → негайний перерахунок залежних операцій і
  показ нового впливу на дату замовлення.
- **FR-GANTT-08** Кнопка «Критичний шлях» підсвічує ланцюжок критичних операцій
  обраного замовлення.
- **FR-GANTT-09** Вертикальна лінія «Сьогодні» завжди відображається.

## Технічне

- **TC-STACK-03** Гантт: `dhtmlx-gantt` (Community Edition).
- Логіка (мапінг, кольори, перерахунок при drag) — чисті функції, тестуються.

## Сценарії тестування

### Сценарій A — Групування по РЦ/ГРЦ і кольори
```
Вхід: операції на РЦ-1 (ГРЦ-1) і РЦ-2 (ГРЦ-2), статуси ok / late / blocked-material
Очікування (buildGanttData):
  вузли-групи на кожну ГРЦ, вузли-РЦ під ними, операції під своїми РЦ
  кожна операція має клас кольору за статусом; locked → штрихування
```

### Сценарій B — Drag перераховує залежні операції
```
Вхід: маршрут вузла з op10 → op20 (Finish-to-Start, міжопераційний день)
Дія: op10 перетягнуто пізніше
Очікування (applyManualMove):
  op20 стартує не раніше початку наступного робочого дня після нового кінця op10
  plannedReadyDate замовлення оновлюється; op10 позначена закріпленою
```

### Сценарій C — Drag раніше не тягне залежні назад
```
Дія: op10 перетягнуто раніше
Очікування: op20 не зсувається раніше (лишається на місці); критичний шлях/дата
  перераховані коректно
```
