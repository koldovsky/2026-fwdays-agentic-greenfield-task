# Specs: data-import

Вимоги взяті з PRD v0.3 (capability `data-import`). ID зберігаються для трасування.

## Функціональні вимоги

### Завантаження файлів
- **FR-IMP-01** Приймати файли з 1С через drag-and-drop або кнопку; кожна таблиця
  завантажується окремо у відповідну зону. Формати: `.xlsx`, `.csv`.

### Таблиці-звіти
- **FR-IMP-02** Замовлення: номер, номенклатура готового виробу, кількість,
  одиниця виміру, кінцева дата здачі, пріоритет (опційно).
- **FR-IMP-03** BOM: батьківська номенклатура, дочірня номенклатура, кількість на
  одиницю, рівень вкладеності, тип вузла (деталь / підзбірка / купований матеріал).
- **FR-IMP-04** Маршрути (МК): номенклатура, номер операції, назва операції,
  Група РЦ, нормативна тривалість у хвилинах на одиницю.
- **FR-IMP-05** Групи РЦ і РЦ: код ГРЦ, назва ГРЦ, перелік РЦ; для кожного РЦ —
  код, назва, потужність (хв/зміну), змін на добу, ефективність (%),
  дозволені типи операцій.
- **FR-IMP-06** Залишки: номенклатура, склад, кількість, одиниця, дата знімку.
- **FR-IMP-07** План надходжень: номенклатура, дата надходження, кількість,
  статус (підтверджено / очікується).
- **FR-IMP-08** Виробничий календар: дата, тип дня (робочий / вихідний /
  скорочений), робочі години; для всіх РЦ або конкретного РЦ.

### Валідація, diff, редагування
- **FR-IMP-09** Валідувати кожен файл одразу; показувати таблицю помилок
  (рядок, поле, причина); при критичних помилках блокувати «Запустити планування».
- **FR-IMP-10** При повторному завантаженні показувати diff (нові / змінені /
  видалені рядки).
- **FR-IMP-11** Усі таблиці доступні для перегляду і редагування в браузері без
  повторного завантаження файлу.

### Персистентність
- **NFR-SAVE-01** Поточний сеанс (усі таблиці) автоматично зберігається в IndexedDB
  і відновлюється після перезавантаження браузера.
- **NFR-DATA-01 / BC-PRIV-01** Дані не покидають клієнт; парсинг лише в браузері.

## Сценарії тестування

### Сценарій 1 — Валідне замовлення
```
Вхід (orders):
  | номер | виріб | кількість | одиниця | дата       | пріоритет |
  | O-1   | A     | 5         | шт      | 2026-03-01 | 1         |
Очікування:
  data = [{ id: 'O-1', productId: 'A', qty: 5, dueDate: 2026-03-01, priority: 1 }]
  errors = []
```

### Сценарій 2 — Порожнє обов'язкове поле
```
Вхід (orders): рядок з порожнім «виріб»
Очікування:
  errors містить { row: 1, field: 'productId', reason: 'обов'язкове поле',
                   severity: 'error' }
  рядок не потрапляє у data
```

### Сценарій 3 — Некоректне число / дата
```
Вхід (orders): кількість = 'abc', дата = 'not-a-date'
Очікування:
  errors містить помилку для field 'qty' і field 'dueDate' (severity 'error')
```

### Сценарій 4 — Невалідний enum
```
Вхід (bom): тип вузла = 'gadget'
Очікування:
  errors містить { field: 'type', reason: містить перелік допустимих, error }
```

### Сценарій 5 — Diff при повторному імпорті
```
Попередній: [O-1 qty 5, O-2 qty 3]
Новий:      [O-1 qty 7, O-3 qty 1]
Очікування:
  TableDiff: changed=1 (O-1, поле qty), removed=1 (O-2), added=1 (O-3)
```

### Сценарій 6 — РЦ і ГРЦ з одного звіту
```
Вхід (resourceCenters): 2 рядки РЦ у групі G1
Очікування:
  rcGroups = [{ id: 'G1', rcIds: ['RC-1','RC-2'] }]
  resourceCenters має 2 записи з groupId 'G1'
```

### Сценарій 7 — Результат сумісний зі ScheduleInput
```
Усі сім таблиць валідні → зібраний об'єкт відповідає інтерфейсу ScheduleInput
бібліотеки планування (orders, bom, routes, rcGroups, resourceCenters,
stock, plannedReceipts, calendar)
```
