# Specs: scheduling-algorithm

Вимоги взяті з PRD v0.3. ID зберігаються для трасування.

## Функціональні вимоги

### BOM expansion
- **FR-BOM-01** Розгортання BOM рекурсивно з множенням кількостей на кожному рівні
- **FR-BOM-03** Виявлення спільних вузлів між замовленнями і консолідація потреб
- **FR-BOM-04** Підзбірки без залежностей між собою можуть плануватися паралельно
- **FR-BOM-05** Батьківський вузол не стартує раніше завершення всіх дочірніх

### MRP
- **FR-MRP-01** Брутто-потреба = розгортання BOM × кількість замовлення
- **FR-MRP-02** Нетто-дефіцит = брутто − залишки − надходження до дати старту операції
- **FR-MRP-04** Матеріал без надходжень = 'critical-deficit'
- **FR-MRP-05** Кожен дефіцитний матеріал пов'язаний зі списком заблокованих замовлень

### Scheduling
- **FR-SCHED-02** Основний режим — backward scheduling від дати замовлення
- **FR-SCHED-03** При backward старт < today → switch to forward, зафіксувати delayDays
- **FR-SCHED-04** Міжопераційний час = старт наступної операції не раніше початку наступного робочого дня
- **FR-SCHED-05** Залежність між операціями в маршруті: Finish-to-Start
- **FR-SCHED-06** Залежність між вузлами BOM: всі дочірні завершені → батько може стартувати (+ міжопераційний день)
- **FR-SCHED-07** Вибір РЦ всередині ГРЦ: мінімальне завантаження + дозволений тип операції
- **FR-SCHED-08** Якщо всі РЦ ГРЦ перевантажені → найраніший вільний слот
- **FR-SCHED-09** CR = (dueDate − today) / remainingDurationDays; менший CR = вищий пріоритет при конфлікті
- **FR-SCHED-10** Критичний шлях — найдовший ланцюжок операцій що визначає дату готовності
- **FR-SCHED-11** Функція викликається двічі з різним mode → повертає 2 незалежних ScheduleResult

## Сценарії тестування

### Сценарій 1 — Просте замовлення без дефіциту
```
Вхід:
  1 замовлення, виріб A
  BOM: A → [B, C]; B → [D]; C → [D]  (D — спільна деталь)
  Маршрут D: Оп.10 (ГРЦ-1, 60 хв), Оп.20 (ГРЦ-2, 30 хв)
  Маршрут B: Оп.10 (ГРЦ-1, 45 хв)
  Маршрут C: Оп.10 (ГРЦ-3, 30 хв)
  Маршрут A: Оп.10 (ГРЦ-4, 20 хв)
  РЦ: по одному в кожній ГРЦ, потужність 480 хв/день, 1 зміна
  Залишки: достатньо всіх матеріалів
  dueDate: через 10 робочих днів

Очікуваний результат:
  order.delayDays = 0
  операції D виконуються раніше B і C
  операції B і C можуть виконуватись паралельно
  операція A виконується після B і C
  deficits = []
```

### Сценарій 2 — Backward дає старт в минулому
```
Вхід:
  1 замовлення, dueDate = сьогодні + 1 день
  сумарна трудомісткість = 3 дні

Очікуваний результат:
  order.delayDays > 0
  всі операції отримали forward-розклад від today
  plannedReadyDate = today + ~3 дні
```

### Сценарій 3 — Дефіцит матеріалу
```
Вхід:
  матеріал M: залишок 0, надходжень немає
  операція Op-5 споживає M

Очікуваний результат:
  Op-5.status = 'blocked-material'
  deficits містить запис для M з netDeficit > 0
  earliestCoverDate = null
  замовлення, що містять Op-5, є в blockedOrderIds
```

### Сценарій 4 — Конфлікт двох операцій на одному РЦ
```
Вхід:
  2 замовлення, обидва мають операцію на ГРЦ-1
  ГРЦ-1 має тільки 1 РЦ
  Замовлення A: dueDate = today + 5, трудомісткість 2 дні  → CR = 2.5
  Замовлення B: dueDate = today + 3, трудомісткість 2 дні  → CR = 1.5

Очікуваний результат:
  Замовлення B отримує слот першим (менший CR)
  Замовлення A зсувається на наступний вільний слот
```

### Сценарій 5 — Два режими дають різні результати
```
Вхід:
  3 замовлення з різними dueDate і трудомісткостями

Очікуваний результат:
  schedule(input, 'min-lateness').metrics.lateOrdersCount
    ≤ schedule(input, 'min-idle').metrics.lateOrdersCount
  schedule(input, 'min-idle').metrics.avgLoadPct
    ≥ schedule(input, 'min-lateness').metrics.avgLoadPct
```

### Сценарій 6 — Перфоманс
```
Вхід:
  1000 замовлень
  глибина BOM = 4 рівні, 5 вузлів на рівень
  8 операцій на вузол
  20 ГРЦ по 2 РЦ
  горизонт = 3 місяці

Очікуваний результат:
  час виконання schedule() < 30 секунд
  результат детермінований (два однакових виклики = однаковий результат)
```

### Сценарій 7 — Спільна деталь між замовленнями
```
Вхід:
  2 замовлення, обидва містять деталь D в BOM
  D: потреба 10 шт від замовлення 1, 15 шт від замовлення 2

Очікуваний результат:
  D планується як один блок: effectiveQty = 25 шт
  операції D з'являються в розкладі один раз (не двічі)
```
